# L4 像素容差标定记录

本目录保存 **Figma 原稿截图** 与当时的 **本地渲染截图**，用于标定 L4 像素门禁的
容差区间。它们是历史取证，不是现行门禁基线。

## 为什么单独存放

2026-09-11 的帧级取证产出的是 **应用界面**（1920×1080 桌面态）的 Figma 原稿与
本地预览截图。它们记录的是当时的设计状态，且与 `design/preview/` 的设计规范
预览页不是同一画面，因此**不能**作为 `npm run test:pixel` 的门禁基线——那样会
拿完全不同的两张图作比较。

现行门禁基线在 `design/preview/baselines/`，规则见该目录的 README。

## 实测结果

同一界面，Figma 原稿 ↔ 本地渲染，1920×1080，通道容差 8：

| 状态   | 参考尺寸  | 实际尺寸  | 差异像素 | 差异占比    |
| ------ | --------- | --------- | -------- | ----------- |
| 展开态 | 1920×1080 | 1920×1080 | 464,616  | **22.406%** |
| 收纳态 | 1920×1080 | 1920×1080 | 349,277  | **16.844%** |

> Figma 导出尺寸为 1920×1081，本地为 1920×1080，差 1px 边框；比对前按
> `allowCrop` 裁剪到共同区域。

## 差异形态解读

差异图（`docs/evidence/frame-accuracy-2026-09-11/` 同源）显示：

- 差异呈**细密网点状**遍布全画面 —— 点阵画布背景在两个渲染器下相位不同；
- 侧栏、画布容器、卡片、对话框等**结构性元素轮廓清晰对齐**；
- 差异不呈成片实心色块。

结论：**差异来自渲染细节，不是布局错位**。这直接支撑了"严格逐点像素相等不可
达成"的技术判断。

## 容差设定的含义

- 差异占比 **不能直接当作"当前实现错了"**——需要看差异形态；
- 结构性错位表现为**成片实心色块**，与上述网点状噪声形态截然不同；
- 因此 L4 门禁采用**有界差异 + 人工复核差异图**双判定，而不是单看数字。

## 复现方式

```bash
node scripts/figma-audit/cli.mjs diff \
  --snapshot <快照> \
  --actual <本地渲染图目录>
```
