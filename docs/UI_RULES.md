# KK Studio UI 规则手册 v2.0

> 定位：**先有规则，后有界面**。本文件是 UI 的约束源，不是 UI 的描述。
> 本文件只管「规则」——什么必须这样、什么绝对不行。
> **所有数值（字号/间距/圆角/控件高/图标/层级）只在 [`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md) 定义一次**；
> 本文件出现数值时，那个数值本身就是规则（如"同屏主按钮 ≤ 1"）。
>
> 入口见 [`UI_INDEX.md`](./UI_INDEX.md)。页面布局类型见 [`UI_ARCHETYPES.md`](./UI_ARCHETYPES.md)。

---

## 0. 效力与优先级

```
业务状态定义 → 语义 Token（DESIGN_TOKENS）→ 组件契约（本文 §7）→ 页面实例（UI_ARCHETYPES）
```

上层只能引用下层，**禁止反向推导**（"这页看起来需要 30px" 不构成新增档位的理由）。
页面/组件内**禁止出现颜色、字号、间距、圆角字面量**——字面量是规则缺口，不是设计自由。

## 1. 规则层（先于 UI 存在）

### 1.1 状态定义（唯一真源）

所有可交互元素共用这一套状态机，不允许某组件自创状态。

| 状态 | 触发 | 背景 | 边框 | 文字 | 焦点环 | 光标 | 可点 |
|---|---|---|---|---|---|---|---|
| `default` | 静止 | `bg-elevated` | `border-default` | `text-primary` | 无 | pointer | ✅ |
| `hover` | 指针悬停 | `bg-elevated` 升级级 | `border-default` | `text-primary` | 无 | pointer | ✅ |
| `active` | 按下 | 再升一级 | `border-strong` | `text-primary` | 无 | pointer | ✅ |
| `selected` | 选中/当前项 | `accent-soft` | `border-accent` | `text-accent` | 无 | default | ✅ |
| `focus-visible` | 键盘聚焦 | 同 `default` | — | 同 `default` | `focus-ring` 2px / offset 3px | pointer | ✅ |
| `disabled` | 不可操作 | `bg-surface` | `border-subtle` | `text-disabled` | 无 | not-allowed | ❌ |
| `loading` | 异步进行中 | 同 `disabled` | 同 `disabled` | 同 `disabled` | 无 | progress | ❌ |

约束：
- `hover` 与 `selected` **不可叠加成第三种颜色**；选中项 hover 只改明度不改色相。
- **`selected` 优先用描边而非填色**（1px accent + inset ring），避免与 hover 背景打架。
- `disabled` 必须 accompanying **原因**（title / tooltip），不能只有灰掉。
- `focus-visible` 只在键盘路径出现，鼠标点击不触发。

### 1.2 数据流向（单向）

```
业务状态（store 唯一真源）
   ↓ 映射为语义名（success / warning / danger / accent / muted）
语义 Token（--kk-semantic-*）
   ↓ 组件变体（variant = primary | secondary | ghost | danger）
实例属性（颜色、图标、文案）
```

- 组件**不感知具体业务**，只感知语义名。
- 同一语义名在任何页面必须落到同一个 Token。
- 反向禁止：不允许"这个页面把 warning 改成紫色"。

### 1.3 交互约束（通用）

| 约束 | 内容 |
|---|---|
| 主次分明 | 每个页面/对话框**有且仅有一个主操作**（primary），其余为 secondary / ghost |
| 位置可预期 | 对话框主操作在右下、次操作在其左；移动端主操作置顶通栏 |
| 破坏性操作 | 删除/清空必须二次确认，且视觉上走 `danger` 语义，不放主操作位 |
| 异步反馈 | 任何 >300ms 的操作必须有 `loading`，>3s 必须可取消且有进度 |
| 结果反馈 | 成功/失败都落 toast；失败 toast 带"重试"入口 |
| 路径可回退 | 每级页面有明确返回，不使用"点空白返回"这类隐式路径 |
| 焦点可预期 | Escape 只关最上层并回焦触发点；菜单转弹窗保留稳定入口 |

### 1.4 交互行为契约（控件级，合并自 UI-STANDARDS §5）

- **键盘**：所有弹层/菜单 Escape 先关闭并回焦触发按钮；二次 Escape 才取消卡片选择；方向键 / Home / End / Enter / Space 可用；焦点可见（`focus-visible` 2px / offset 3px）。
- **画布**：无限画布无页面滚动条（`overflow: clip`）；缩放保留目标锚点、不移动节点；菜单操作不触发拖动；卡片拖动 / 键盘移动 / 删除保留草稿。节点内部禁用浏览器原生 `dragstart`，避免图片拖放取消 Pointer Events；外部文件 drop 保留。图片卡片的透明外壳不截获鼠标，可见子区域和跟随操作恢复命中，避免遮挡可见连线。
- **连线**：悬停/聚焦/选中显示删除按钮，移向删除按钮期间保持显示，点击外部解除激活；**删除只移除连接并提供撤销，保留两端节点与内容**；节点移除同步清理悬空连接。删除当次操作内回焦画布。来源节点位置与草稿不得因连接操作改变。
- **右侧跟随加号**：按节点坐标定位，保持屏幕尺寸（桌面 28px，宽度 ≤800px 时 44px），点击打开共享类型菜单，创建下游卡片并选中/聚焦；**自动定位按屏幕像素预留按钮空间**，不能仅预留缩放后的世界坐标间距。菜单键盘移动不滚动页面。
- **示范素材**：显式入口加载图片/短视频/音频/可编辑文案；节点标注"示范素材"，模拟处理标注"演示处理中"；**不冒认供应商生成成功、积分消费或保存服务器**；不依赖第三方 API；取消不得出现迟到结果。
- **弹层/预览**：关闭与 Escape 回焦；媒体真实可播放（音视频不得用海报假装），加载/错误可恢复；文案可编辑复制。
- **搜索与收藏**：顶部短横线只表示拖拽/装饰；分类选中线必须沿分类栏底部分割线移动，不能以顶部短横线或整块背景替代。分类横向溢出时可滚动，Left/Right/Home/End 与选中线同步。
- **创作输入**：首页默认只露出添加、模型、Skill、语音、模式和发送；插件、伙伴、批量及数据设置由明确的添加入口访问且保留状态。独立提示词库按钮和空提交状态行不占据首页。文本、附件和反馈增长时外框向下扩展；静态 Figma 外框不裁切操作。
- **对话面板**：展开状态由明确的展开/收起按钮控制，点击画布、空白处、其他操作或 Escape 不收起。展开前后开关保持同一屏幕坐标；手机对话入口与底部导航共享状态。
- **无障碍**：语义角色、aria 状态（`pressed` / `checked` / `expanded`）、长中文无截断、四视口（1920/1440/768/390）无页面溢出。

### 1.5 画布 HUD 布局契约（合并自 UI-STANDARDS §9）

- 屏幕上的工具（任务、示范、导航、对话入口）统一组合于 `CanvasHud`，由同一个 `useCanvasViewport` 计算实际可用内容宽度（排除画布边框、停靠聊天与组间距）。**窄屏打开聊天抽屉时也必须扣减可用宽度**，保证底栏不被面板覆盖。顶部控件保持同一行和固定 8px 组间距。
- **有分工差异的控件不能统一拉伸**：不能把原稿不同尺寸的按钮压成一致宽度，也不能重新加入已废止的"收起工具栏"。
- **顶部对齐**：桌面和平板的对话开关、侧栏折叠、任务入口、缩放与整理以同一水平中心线对齐；手机采用双行 HUD 和触控命中区。窄屏底栏按实际可见按钮占宽，不留无操作的尾部空白。
- 跟随加号和删线按钮按世界坐标锚定：先抵消画布缩放，再按屏幕坐标居中/偏移。菜单始终在按钮下方留 6px。
- 工具栏收起/展开保留焦点和 `aria-expanded`，关闭残留菜单。固定网格不使用宽度插值（会在窄胶囊中提前铺开子按钮）。
- 验证需同时覆盖**窗口宽度 × 面板状态 × 画布比例**三个维度，断言真实矩形交叠和命中位置；只检查页面 `scrollWidth` 不足以发现控件相互覆盖。

### 1.6 复用契约（合并自 UI-STANDARDS §13 / §10）

- **同一组令牌分层**：文字、图标、容器按同一组共享令牌分层；禁止在单个页面重新定义同义字号。
- **图标槽位与命中框分离**：视觉图形可以小于槽位，但**命中框和对齐基线不能跟随图形缩放漂移**。
- **间距只从共享间距档位选择**；同一 `canvas-hud-right` 内的组间固定 8px。
- 复用检查以真实矩形为准：至少覆盖 1071×698 / 1440×900 / 1600×1047 / 1920×1080；检查导航等距、标题按钮尺寸、输入控件不溢出、工具栏与会话面板无交叠。
- **手势归属统一**（`useCanvasPointer`）：选择工具下左键从空白起拖为框选、从卡片可见内容起拖为移动；中键/右键或抓手工具平移视图。Shift 点击/框选追加多选；拖动已多选卡片同步移动。Space 临时平移，V/H 切换工具。Escape / 指针取消 / 窗口失焦取消正在进行的手势并恢复坐标。
- **框选几何使用可见卡片内容**，不使用透明的编辑器外壳；框选和多选时不展开编辑器。
- **底栏**：复用原稿六槽；箭头是选择/抓手菜单入口，心形打开全局喜欢收藏（不依赖选中节点）。现有结果卡片收藏与全局收藏共用同一 `favoriteIds` 状态。
- **菜单层级**：菜单打开后续弹窗前，必须先把焦点放回持久触发按钮；打开后互斥、上下键/Home/End 导航、Escape 回焦。
- **来源标注纪律**：未取得原稿时序/几何证据的动效与尺寸，必须标注为"工程补充"，**不得称"还原原稿"**。取得真实值后按原稿替换。

### 1.7 侧栏契约（合并自 UI-STANDARDS §11）

- 收起/展开宽度**不插值**，避免子控件提前挤入收起轨道与画布居中抖动；展开文字用既有 140ms 透明度时序。
- 单色 SVG 使用 mask 继承颜色；多色图标保留原始资源。
- ≤800px 自动显示收起轨道；展开以抽屉覆盖，保留画布起点，顶部菜单与侧栏按钮消费同一 layout hook。关闭、Escape 及隐藏已聚焦分组时回到持久切换按钮。
- 粗指针将底部控件命中扩大至 44px 并拉开间距；**实际鼠标稿尺寸不随窄屏强行放大**。
- 窄屏将设置移到搜索上方，与画布底栏无交叠。
- 桌面侧栏与对话面板分隔条支持拖动和键盘方向键；Home 到最小值、End 到当前布局可达最大值、Shift+Home 恢复设计默认宽度。`aria-valuemax` 随窗口与相邻面板变化，平板/手机隐藏分隔条。此为工程补充交互。

## 2. 尺寸规则

### 2.1 控件档位（按族分档）

取值表在 [`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md) §4（`icon` / `button` / `field` / `chip` / `shell` 五族）。
**本文件不复制那张表**——两处数值必然漂移（v2.0 就发生过一次）。

> **为什么不是单一 4 档**
> 用"高度"一个维度表达"这是什么控件"是不充分的：同样 32px，按钮该有 12 内距 + 16 图标，
> 输入框该有 12 内距 + 16 图标，菜单项该有 8 内距 + 16 图标——它们不该共用一个档。
> 分族之后，**同名档位天然锁定一整组参数**，选档时问的是"这是什么控件"，不是"选个数字"。

**选档四问**（按顺序回答，答完档位即确定）

1. **是纯图标吗？** 是 → `icon` 族，在 20/24/28/32/40 里选。
2. **有文字且可点？** 是 → `button` 族，在 28/32/40/44 里选。
3. **是输入类吗？** 是 → `field` 族，在 28/32/40 里选。
4. **是状态标注 / 胶囊吗？** 是 → `chip` 族，在 20/24/28 里选。
都不是 → 它是**容器**，走 `shell` 族（外壳定内距，内部控件仍按 1–4 选档）。

**硬性约束**
- **高度必须落在封闭轴 `20 / 24 / 28 / 32 / 40 / 44` 上**。
- **同一容器内的同类控件必须同档**。跨档出现即为缺陷（"同一按钮两种大小"的唯一判定标准）。
- **禁止档位表外的"量取值"**（30 / 31 / 36 / 22 / 21 / 25 等）。Figma 量取值必须归到最近档，不得直接落地。
- 原稿指定、确有还原必要的来源几何走**冻结值**（[`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md) §4.6），
  只用于指定位置，不得扩散。
- 运行态历史越界值的归位方案见 §10.2。

### 2.2 图标（三档 + 两个封闭例外）

| 档位 | 配对字号 | 适用 |
|---|---|---|
| `icon-sm` | 12 | 密集列表、表格行内 |
| `icon-md` | 13 | 默认：按钮、输入框 |
| `icon-lg` | 14–16 | 主行动按钮、工具栏 |

两个**封闭例外**（不再扩容）：
- **头像**：按容器定（列表 / 卡片 / 详情），一个区域内只一个值。
- **品牌 Logo**：属于品牌位，不属于图标位，按出现位置定尺寸。

**禁止**：为某个页面新增图标档位；把 Logo 尺寸并入图标层级。

### 2.3 字号（绑定规则）

九档字阶的**取值**见 [`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md) §3，本文件只管四条绑定规则：

1. 同层级文本必须同 `fontFamily + fontSize + fontWeight + lineHeight`——四者任一不同即视为不同层级，需能说出理由。
2. 中文混排统一中文无衬线；纯拉丁/数字/型号/版本号用拉丁无衬线；代码/日志用等宽。
3. **数字高亮统一 `tabular-nums`**，防止数值跳动造成视觉抖动。
4. **产品内界面字号封顶 24**；32 / 48 只用于营销落地页。

### 2.4 动效（规则层）

取值见 [`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md)。硬约束：

- 只用共享时序令牌，禁止自写时长/曲线。
- 入场动效只用于弹层/面板，不用于列表项逐条入场。
- **拖拽/平移中禁用动画与过渡**，避免与变换冲突。
- **`prefers-reduced-motion: reduce` 必须全局关闭动画 / 过渡 / 平滑滚动**。
- 未取得原稿关键帧证据时，动效登记为"工程补充"，不称"还原原稿动画"。

## 3. 间距规则（双标尺，不可混用）

本文件只定**职责划分**；档位取值见 [`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md) §5。

### 3.1 组件内标尺（4px 基准）

用于：控件内边距、图标与文字间距、列表项间距、卡片内边距。
**禁止**用页面节奏标尺做组件内边距。

### 3.2 页面 / 容器标尺

用于：页面外边距、栅格列间距、区块之间、大分区之间。
**禁止**用组件标尺撑页面分区——大处不够、小处太松的根源。

### 3.3 成对关系

**不许自行挑数值**，按 [`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md) §5.4 的成对表取用。

**约束**
1. 容器左右内边距必须用响应式容器内距 token，不许每台设备手写。
2. 同一列表的项间距**必须一致**，禁止 12 挨着 16。
3. 分区之间的间距必须**明显大于**分区内部间距（至少差一档），否则层级读不出来。

## 4. 圆角规则

### 4.1 档位取值

见 [`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md) §6.1（九档）。本文件只定语义归属优先级：

- 输入 / 普通控件取 control 档；
- 菜单 / Popover 取 menu 档；
- Modal 内容面板取 panel 档；
- 卡片取 card 档；
- 开关 / 胶囊 / 徽标取 full 档。

**禁止**：把所有弹窗套成同一个 menu 圆角；因为卡片用 card 档就去改所有画布节点几何。

### 4.2 嵌套公式（强制）

```
内圆角 = 外圆角 − 内边距      （不得相等，不得更大）
```

成对关系表见 [`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md) §6.2。

**规则**
1. **嵌套的两层绝对不许用同一个圆角值**——这是最常见的"看着歪"根因。
2. 若需 12 或 4 的内边距，按公式算出的值可能落到 0 或负数 → 内层取 xs 档或直角，**不要硬套公式产生不在轴上的值**。
3. **信息密集容器（表格 / 数据 / 代码 / 终端）禁用 panel / card / full 档**。
4. 描边圆角：**内描边 = 元素圆角**；**外描边（focus ring）= 元素圆角 + 焦点边框宽**。

## 5. 层级规则

### 5.1 面的层级（逐级递进）

4 级表面层级与跳跃约束见 [`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md) §2.1。补充规则：

- 每升一级必须配一次阴影升级，**不允许跳过**（L1 直接套 L3 阴影）。
- **选中态用描边或中性选择色，不要用背景层级冒充选中**。

### 5.2 阴影与 z-index

取值见 [`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md) §2.2（阴影 3 级 + z-index 7 档）。

- **禁止出现 `z-index: 9999` 之类的魔法值**，一律走 token。
- 阴影颜色随主题走，**不允许写死 `rgba(0,0,0,x)`**。

### 5.3 文字层级（3 级）

`primary`（正文/标题）· `secondary`（说明/次级）· `tertiary`（元信息/占位）。
同一段区域内**层级跨度不超过 2 级**。
禁用 `disabled` 表达层级——它只表达不可操作。

### 5.4 强调色层级

- 强调色**只给主行动**；**同一屏幕主按钮 ≤ 1**。
- 次要 / 第三级操作走中性色或文字按钮，不用强调色堆叠。
- 多个强调色并列 = 没有强调。

## 6. 对齐规则（视觉对齐 ≠ 数据对齐）

这是最容易漏的一类缺陷，六条逐条检查：

1. **基线对齐优先于盒对齐**
   同一列的文本必须同 `fontSize + lineHeight + fontFamily + fontWeight`。
   不同字重/字族即使盒子对齐，视觉基线也会偏——这是"数据对齐但看着歪"的主因。

2. **图标槽固定**
   有图标的行与无图标的行，文字左边缘必须一致。
   做法：预留固定宽度图标槽（= 图标档位尺寸），无图标时留空槽，**不要用 gap 顶开**。

3. **内边距对称**
   同一 pill / 行 / 卡片的左右内边距必须相等。
   唯一例外：为滚动条或右箭头预留的位置，且必须写成规则而不是随手调。

4. **不用 padding 制造行高**
   行高用固定 `height` + 交叉轴居中。
   用 `padding-top` 把 28px 行撑出来的做法会让文字重心偏下——已列为缺陷。

5. **图标与文字同行**
   图标盒高 = 行高；图标尺寸 ≥ 字号 × 1.25 且 ≤ 行高；图标自身视觉重心居中（圆角/描边图标需留 1–2px 光学补偿）。

6. **数字列右对齐 + 等宽数字**
   数值列必须右对齐并启用 `tabular-nums`，否则小数点无法成列。

## 7. 组件契约（零件规格）

组件**尺寸/圆角/间距全锁定**。完整取值见 [`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md) §7 与 [`DESIGN-SYSTEM.md`](./DESIGN-SYSTEM.md) §基础组件用法表；本表只列**契约红线**。

| 组件 | 契约红线 |
|---|---|
| Button | 同档整组取用（高度+内距+图标+字号+间隙）；主按钮 = accent 填充 + on-accent 文字；同屏 ≤1 |
| Danger | 文字危险与填充危险分开；不受强调色影响；需二次确认 |
| Input | 单行高与按钮同档；**可访问 label**；placeholder 不代替 label；`min-width: 0` |
| Select | 文字可读、键盘可选；原生弹出菜单由系统控制，不声称还原为自定义菜单 |
| Badge | 纯信息无点击角色；不靠颜色单独表达成功/错误（必须有文字或图标） |
| Capsule | 可切换时用 `button + aria-pressed`；不把过滤器当主提交 |
| Switch | `role=switch + aria-checked`；保留 Space 切换与状态持久化；disabled 必须给原因 |
| Card | 与 surface 独立；不再混用 surface 底色 |
| IconButton | 命中区与图形分开；真实图标 + `aria-label`；tooltip/title 不替代名称 |
| Modal | 原生 dialog；**Esc 只关闭顶层并回焦**；外部点击沿用可取消契约，不能丢失进行中操作 |
| Toolbar | 狭窄窗口可操作且不遮挡；保持真实行为和来源几何 |
| MenuItem | 缩进走共享缩进 token，不手调 |
| Composer | 几何由共享输入组件拥有，**禁止在页面或响应式文件再次拼接输入框内部尺寸** |

**历史重灾区，改完必自检**：Input、IconButton、Toolbar、二级菜单（Submenu）。

## 8. 图标资产来源（两级，不扩第三级）

1. **Figma 导出资源**（权威）：`public/design/figma/`。已缓存来源的 SVG 直接从原稿下载，**禁止手绘替代**。

## 9. 门禁与自查

### 9.1 可执行门禁

`npm run ui:check`（已纳入 `npm run verify`）检查：
- `src` 下 CSS/TSX 的具体颜色值及出现次数；
- 未声明且无回退值的 CSS 令牌；
- TypeScript AST 中的 Lucide 导入符号、Iconsax 导入入口；
- 组件 300 行边界。

新文件默认没有遗留豁免。新增颜色只进 `global.css` / `ui-tokens.css` 并在本文登记用途，表现层只消费令牌。

### 9.2 禁止清单（违反即退回）

1. 🚫 组件/页面内出现颜色、字号、间距、圆角**字面量**
2. 🚫 同一容器内按钮跨档
3. 🚫 档位表外的"量取值"（30 / 31 / 36 / 22 / 24 等）
4. 🚫 同一圆角配不同内边距
5. 🚫 用 `padding-top` 制造行高
6. 🚫 同类行使用不同字族/字重
7. 🚫 新增图标尺寸档位（需评审后入册）
8. 🚫 跨级使用阴影/层级
9. 🚫 组件内直接引用 Tier-1 原始色（只允许语义色）
10. 🚫 一屏内多个强调色主操作
11. 🚫 把"代码已有 / 测试通过 / Figma 已读取"当作视觉完成证据
12. 🚫 未取到原稿证据却标注"还原原稿"

### 9.3 每次改动前后自查清单

- [ ] 新增/修改的元素，尺寸能在 §2 档位中找到？
- [ ] 所属容器内所有同类控件是否同档？
- [ ] 圆角是否符合嵌套公式（内 = 外 − 内边距）？
- [ ] 同类容器的圆角与内边距是否成对一致？
- [ ] 同一列文本四要素（族/号/重/行高）是否一致？
- [ ] 有图标行与无图标行的文字左边缘是否一致？
- [ ] 所有可交互元素是否覆盖 §1.1 的状态机？
- [ ] 页面是否只有一个主操作？破坏性操作是否二次确认？
- [ ] 异步操作是否有 loading / 可取消 / 结果反馈？
- [ ] 是否有字面量逃逸（颜色/尺寸写死）？
- [ ] 图标来自 §8 的两级来源，没有引入第三套图标库？
- [ ] 动效是否只消费共享时序，reduced-motion 是否生效？
