# KK Studio UI 规则手册（新版 Figma 治理基线）

> 本文件只描述可复用的零件和交互规则。四个 Figma 治理页面是唯一设计
> 基线；本文件不得被旧页面草稿、旧 CSS 或历史类型表反向覆盖。
>
> 业务状态、数据流和问题矩阵见
> [`docs/changes/2026-09-29-figma-ui-governance/spec.md`](./changes/2026-09-29-figma-ui-governance/spec.md)。
> 数值 token 的运行时来源是 `src/styles/tokens.css`。

## 1. 规则层级

规则顺序固定为：

`业务状态 → 语义 token → 共享组件 → 页面模板 → 页面实例`

上层只能消费下层，不能在页面或断点样式里创造同义 token。发现冲突时按以下
顺序裁决：四个 Figma 治理页面、`tokens.css`、本文件和模板文档、历史归档。

## 2. 业务状态与操作门禁

所有生成入口共用 `idle`、`editing`、`validation-error`、`ready`、`queued`、
`running`、`success`、`failure`、`cancelled`、`offline`、
`service-unconfigured`。状态只能由 `src/domain/uiGovernance.ts` 的纯函数
推导，组件不得自创“处理中”或“已完成但未写入资产”等隐含状态。

### 2.1 操作约束

- `idle`、`editing`、`validation-error`、`offline`、`service-unconfigured` 只能
  在满足各自条件后进入提交；未配置服务时提交和测试生成始终禁用。
- `queued`、`running` 禁止重复提交；`running` 禁止修改任务参数，但保留查看
  进度和取消。
- `failure` 必须保留重试、原因和恢复路径；`cancelled` 必须显示积分释放结果
  并允许重新提交。
- 所有提交按钮、Enter/快捷键和菜单命令必须经过同一个状态谓词。
- 禁用态必须有可读原因，不能只降低透明度；异步操作必须在 100ms 内呈现
  loading 或状态文字。

### 2.2 数据事务

`输入/上传 → 模型与参数 → 预校验 → 冻结积分 → 创建任务 → 生成结果 → 写入资产 → 收藏/喜欢`

预校验不通过不得冻结积分；任务创建失败立即释放冻结；结果写入资产后才允许
收藏或喜欢；`favorite` 和 `liked` 永远分开保存和切换。

## 3. Token 与尺寸规则

### 3.1 唯一来源

- `src/styles/tokens.css`：`--kk-*` 语义 token 的唯一源。
- `src/styles/ui-tokens.css`：旧 `--ui-*` 名称的兼容映射，只能引用 `--kk-*`。
- `src/styles/ui-governance.css`：文字、按钮、图标槽、命中区和截断工具类。
- `src/components/UiIcon.tsx`：工程补充图标的唯一映射；Figma 导出的 SVG
  从 `public/design/figma/` 直接使用。

### 3.2 封闭尺寸轴

- 间距使用 4px 网格。
- 控件高度只能是 24、32、40。
- 图标图形只能是 16、20、24；命中区最小 24，关键工具 32，主操作 40。
- 标准按钮四族为 Primary、Secondary、Tertiary、Danger，统一 32px 高、8px
  圆角，并实现 default、hover、pressed、focus、loading、success、failure、
  disabled 状态。
- 页面或组件不得出现未注册的高度、圆角或图标尺寸；外壳例外必须在
  `tokens.css` 注册后才能使用。

### 3.3 文字与截断

产品文字只能消费 Caption `12/16`、Body `14/20`、Body Strong `14/20/600`、
Subtitle `16/24/600`、Title `20/28/700`、Display `26/32/700`。任何可见产品
文字不得低于 12px。单行超长使用省略号，多行说明最多三行并在详情页或提示中
提供完整内容。

## 4. 颜色、层级和反馈

- 组件只使用语义颜色，不写页面级颜色字面量。
- 紫色只用于唯一 Primary、键盘焦点环和关键状态；同一视图不得堆叠多个 Primary。
- 状态必须同时提供颜色和文字/图标，不能只靠色相区分成功、失败或离线。
- 失败文案必须包含原因、影响和下一步；关键结果写入页面状态或记录，toast
  只能作为即时提示。
- 选择态优先用描边或选择 token，不用改变整张卡片的层级来模拟选择。

## 5. 对齐与操作反馈

- 图片卡片单击只选中；预览、重绘、对比等图片操作在选中后显示于卡片上方的
  共享浮动工具栏，不能常驻在图片内部。取消选择、空白点击或 Escape 收起，
  切换卡片只保留当前操作栏。工具栏随卡片移动并保持 32px 标准控件尺寸，
  不随画布缩放缩小命中区；双击图片或工具栏预览按钮打开预览。
- 文本与图标先进入固定槽位，再按相同基线对齐；视觉图形缩放不能改变命中框。
- 同类按钮的高度、圆角、内边距、图标槽和组间距必须一致；一个按钮不能同时
  出现两种尺寸。
- 主操作在页面中有唯一位置，次操作使用 Secondary/Tertiary；危险操作使用
  Danger 并在破坏性动作前确认。
- 弹层、菜单和设置 rail 使用稳定的 Escape、回焦和关闭路径；移动端设置分类
  固定在底部横向 rail，不与顶部入口重叠。
- 侧栏只有收起和展开两个离散状态。收起显示窄 rail，展开使用固定宽度并推动
  工作区；切换图标必须反映当前可执行动作，不能根据动画中间帧改变语义。
- 输入区在手机、桌面和对话面板分别使用注册的几何契约；断点只能调整容器
  位置和宽度，不能复制另一套内部控件尺寸。

## 6. 三态与无障碍

列表、卡片、详情、时间线和画廊都必须提供空、加载、错误三态。加载态保持目标
元素的尺寸和圆角，错误态提供原因、影响、下一步和重试。所有可操作元素可键盘
访问，使用 `aria-pressed`、`aria-checked`、`aria-expanded` 表达状态，焦点环
只在 `:focus-visible` 出现。

## 7. 新组件检查清单

- [ ] 已从 11 个业务状态推导可用/禁用操作，未新增隐含状态。
- [ ] 所有提交路径调用共享状态谓词，服务未接入时没有假成功。
- [ ] 文字、控件高度、图标和圆角都来自 `tokens.css` 或共享类。
- [ ] 同类按钮只有一个尺寸，命中区和视觉图形分离。
- [ ] 页面只有一个 Primary，失败/禁用反馈可读且可恢复。
- [ ] 单行、多行和窄屏文本没有溢出、错位或截断丢失。
- [ ] 空、加载、错误态和键盘路径均有验证证据。
- [ ] 运行 `node scripts/check-ui-standards.mjs` 为 0 项违规。

旧版 9 类型页面、旧字号表和旧封闭轴只在 `docs/archive/` 中保留作为历史证据，
不得作为新功能选型或样式来源。
