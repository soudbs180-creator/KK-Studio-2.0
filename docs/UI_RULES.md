# KK Studio UI 规则手册

> 本文件只描述可复用的零件和交互规则。2026-10-14 当前用户反馈覆盖相冲突的旧视觉约束，裁决从 [UI_INDEX](UI_INDEX.md) 开始；未覆盖的 Figma 基线与历史记录保留溯源。
>
> 业务状态、数据流和问题矩阵见
> [`docs/changes/2026-09-29-figma-ui-governance/spec.md`](./changes/2026-09-29-figma-ui-governance/spec.md)。
> 数值 token 的运行时来源是 `src/styles/tokens.css`。

## 1. 规则层级

规则顺序固定为：

`业务状态 → 语义 token → 共享组件 → 页面模板 → 页面实例`

上层只能消费下层，不能在页面或断点样式里创造同义 token。发现冲突时按以下
顺序由 [UI_INDEX](UI_INDEX.md#2-冲突裁决) 指定；数值从注册 tokens 读取，页面实现不能自建第二套规范。

## 2. 业务状态与操作门禁

所有生成入口共用 `idle`、`editing`、`validation-error`、`ready`、`queued`、
`running`、`success`、`failure`、`cancelled`、`offline`、
`service-unconfigured`。状态只能由 `src/domain/uiGovernance.ts` 的纯函数
推导，组件不得自创“处理中”或“已完成但未写入资产”等隐含状态。

### 2.1 操作约束

- `idle`、`editing`、`validation-error`、`offline`、`service-unconfigured` 只能
  在满足各自条件后进入提交；未配置服务时提交和测试生成始终禁用。
- `queued`、`running` 禁止重复提交；`running` 禁止修改任务参数，但保留查看
  进度和取消。
- `failure` 必须保留重试、原因和恢复路径；`cancelled` 必须显示积分释放结果
  并允许重新提交。
- 所有提交按钮、Enter/快捷键和菜单命令必须经过同一个状态谓词。
- 禁用态必须有可读原因，不能只降低透明度；异步操作必须在 100ms 内呈现
  loading 或状态文字。

### 2.2 数据事务

生成仍按输入/上传 → 模型与参数 → 预校验 → 任务 → 结果 → 原件归档执行；积分冻结/结算仅在真实平台计费能力接入后按其契约处理。喜欢与标签是卡片偏好和分类，可记录创作草稿，不制造生成成功或原件已归档状态。喜欢保持 likedIds；旧收藏保持 favoriteIds，并投影为“收藏”标签，二者独立。兼容与恢复见 [ADR-017](architecture/adr/ADR-017-unified-ui-and-collection-compatibility.md)。

## 3. Token 与尺寸规则

### 3.1 唯一来源

- `src/styles/tokens.css`：`--kk-*` 语义 token 的唯一源，数量以当前源码检查为准，
  不在此固定历史测量数字。
- `src/styles/ui-tokens.css`：旧 `--ui-*` 名称的兼容映射，只能引用 `--kk-*`，
  不作为第二份可加载数值表。
- `src/styles/responsive-content.css`：媒体查询内的响应式覆盖，只覆盖
  `--ui-input-height` / `--ui-button-height` 等少数高度别名，不新增语义。
- `src/styles/ui-governance.css`：文字、按钮、图标槽、命中区和截断工具类。
- `src/components/UiIcon.tsx`：工程补充图标的唯一映射；Figma 导出的 SVG
  从 `public/design/figma/` 直接使用。

### 3.2 封闭尺寸轴

- 间距使用 4px 网格。
- 控件高度只能是 24、32、40。
- 图标图形只能是 16、20、24；命中区最小 24，关键工具 32，主操作 40。
- 标准按钮四族为 Primary、Secondary、Tertiary、Danger，消费 24/32/40 高度与组件语义圆角；文字动作使用胶囊，上传及 IconButton 使用方形圆角命中区。default、hover、pressed、focus、loading、success、failure、disabled 共用相同 token 体系。
- 页面或组件不得出现未注册的高度、圆角或图标尺寸；外壳例外必须在
  `tokens.css` 注册后才能使用。

### 3.3 文字与截断

产品文字只能消费 Caption `12/16`、Body `14/20`、Body Strong `14/20/600`、
Subtitle `16/24/600`、Title `20/28/700`、Display `26/32/700`。任何可见产品
文字不得低于 12px。按钮按内容扩展，常规名称完整显示；只有超出容器可用宽度的长文本才省略，并提供完整可访问名称或 title。图标与可见文字整体居中，截断后仍居中；多行说明在详情或提示中提供完整内容。

### 3.4 Token 化纪律

本节只讲「怎么用token」，数值索引见 [DESIGN_TOKENS](DESIGN_TOKENS.md)，颜色与基础组件见 [DESIGN-SYSTEM](DESIGN-SYSTEM.md)。

**禁止事项**（由 `npm run ui:check` 拦截）：

| 禁止                               | 报错形式                           | 例外                                           |
| ---------------------------------- | ---------------------------------- | ---------------------------------------------- |
| 组件 CSS 写颜色字面量              | `新增颜色字面量 #xxx`              | 仅 `global.css`、`ui-tokens.css`、`tokens.css` |
| 使用未定义令牌                     | `未定义的 CSS 令牌 --xxx`          | 无                                             |
| 直接 import 新 `lucide-react` 符号 | `新增 Lucide 导入`                 | 存量白名单 46 个符号（13 个文件），见下        |
| Iconsax 绕过 `UiIcon`              | `Iconsax 必须通过 UiIcon 映射使用` | 仅 `UiIcon.tsx`                                |
| 组件超300 行                       | `超过 300 行组件边界`              | 无                                             |

`scripts/check-ui-standards.mjs` 同时扫描 `src/**` 下全部 `.css` 与 `.tsx`，`src/main.tsx` 必须加载 `./styles/tokens.css`，否则直接报错。

存量豁免台账是 `config/ui-legacy-baseline.json`（19 个文件、28 个颜色键、46 个 Lucide 符号），脚本按「计数超出 baseline 即报错」消费。**该文件同时承载颜色与 Lucide 两类白名单，不得新增条目来给新代码放行。**

**允许的做法**：

1. 需要新数值时，先在 `tokens.css` 注册语义 token，再在组件里 `var()` 消费。不允许「先写死、以后再抽」。
2. 组件优先消费语义 token（`--kk-color-*`、尺寸轴），其次才用兼容别名 `--ui-*`。新代码不写 `--ui-*`。
3. 组件 CSS 里只写布局与结构（间距用 4px 网格、flex/grid、对齐），颜色、字号、圆角一律 `var()`。
4. 同一数值在 3 处以上重复出现即应提取为 token；重复本身就是待提取信号。
5. 数值语义要能回答「为什么是这个值」。说不出来源的数值不进 `tokens.css`。

**新增 token 的验收要求**：

- 写明语义名称、取值、设计来源（Figma 节点或既有页面实测值）、实际使用者。
- 说明为什么现有 token 不适用。语义相近的 token 必须复用，不新增近义项。
- 通过 `npm run ui:check`，并在浏览器或Desktop 实测截图，不能只凭静态检查通过。
- 同步更新 [DESIGN_TOKENS](DESIGN_TOKENS.md) 的索引表。

**幽灵数值**：不接受 `13.7px`、`7.031px` 这类从Figma 直接抄来的非网格小数。Figma 导出值先归整到最近的封闭轴（间距 4px、控件 24/32/40、图标 16/20/24），归整后才允许进入 token。`ui-tokens.css` 中现存的小数阴影值属存量，新代码不得沿用这种写法。

**命名**：语义 token 用 `--kk-<类别>-<角色>-<变体>`（如 `--kk-radius-panel`）；兼容别名保留旧 `--ui-*` 名不动，只改指向，不重命名。新增时不为了「统一」而批量重命名存量 token。

## 4. 颜色、层级和反馈

- 组件只使用语义颜色，不写页面级颜色字面量。
- 默认强调色为绿色，已显式保存的其他强调色保持。Primary 表达操作层级，普通主要动作使用主题中性高对比表面；颜色用于状态、选择和危险反馈，不能把所有主要动作涂成强调色。普通输入在输入时没有明显外圈或发光，键盘 focus-visible 保留克制且可见的中性提示。
- 状态必须同时提供颜色和文字/图标，不能只靠色相区分成功、失败或离线。
- 失败文案必须包含原因、影响和下一步；关键结果写入页面状态或记录，toast
  只能作为即时提示。
- 选择态优先用描边或选择 token，不用改变整张卡片的层级来模拟选择。

## 5. 对齐与操作反馈

- 图片卡片单击只选中；预览、重绘、对比等图片操作在选中后显示于卡片上方的
  共享浮动工具栏，不能常驻在图片内部。取消选择、空白点击或 Escape 收起，
  切换卡片只保留当前操作栏。工具栏随卡片移动并保持 32px 标准控件尺寸，
  不随画布缩放缩小命中区；双击图片或工具栏预览按钮打开预览。
- 文本与图标先进入固定槽位，再按相同基线对齐；视觉图形缩放不能改变命中框。
- 同类按钮的高度、圆角、内边距、图标槽和组间距必须一致；一个按钮不能同时
  出现两种尺寸。
- 主操作在页面中有唯一位置，次操作使用 Secondary/Tertiary；危险操作使用
  Danger 并在破坏性动作前确认。
- 弹层、菜单和设置导航保持 Escape、回焦与关闭路径。桌面设置使用分类、接入方式与详情；窄屏逐级展示“设置分类 → 接入方式 → 详情”，提供“返回设置分类”“返回接入方式”，服务商目录另有列表/详情与返回路径。连接操作进行中锁定切页、返回与关闭，原因可读；可取消的请求/CLI 操作保留对应入口，结束后恢复导航。当前手机尺寸验证属于响应式 Web，原生 Mobile 由独立工程验收。
- 手机画布选中节点的编辑器使用 `CanvasComposerShell` 和屏幕编辑器 token，脱离世界缩放但仍留在画布的 covered/inert 边界内。复用同一节点草稿和提交动作，模型、参数与展开控件保持屏幕命中尺寸；菜单进入可滚动编辑容器，切回桌面保留草稿。此规则不代表新生成能力或原生 Mobile 已验收。
- 喜欢和标签的固定面板位于画布操作工具栏及屏幕编辑器之上，活动面板位于同类面板之上；共享层级 token 保证关闭和移动按钮可点击，设置遮罩、模态框与标签编辑仍在面板之上。
- 画布HUD及其缩放/背景入口和菜单位于屏幕编辑器之上、喜欢/标签面板之下，入口不能等菜单打开后才提升层级；选中卡片动作避让菜单实际矩形。菜单按画布可用高度滚动，滚动不平移画布。背景按钮提供点状/网格与可见颜色入口，不以不可聚焦的隐藏输入作为操作。手机浅色、深色和短屏下全部比例、背景与编辑器控件必须可命中。
- 生成期间锁定当前节点的提示词、模型、参数、数量和参考图修改，保留取消；结束恢复原草稿。删除本地演示源卡同步结束其等待结果，撤销不能复活没有执行者的进行中状态。
- 设置忙碌状态按操作所有者聚合，结束或卸载只能释放自身锁；MCP握手、工具调用及插件操作不得互相解除导航保护。
- 侧栏只有收起和展开两个离散状态。收起显示窄 rail，展开使用固定宽度并推动
  工作区；切换图标必须反映当前可执行动作，不能根据动画中间帧改变语义。
- 输入区在手机、桌面和对话面板分别使用注册的几何契约；断点只能调整容器
  位置和宽度，不能复制另一套内部控件尺寸。

## 6. 三态与无障碍

列表、卡片、详情、时间线和画廊都必须提供空、加载、错误三态。加载态保持目标
元素的尺寸和圆角，错误态提供原因、影响、下一步和重试。所有可操作元素可键盘
访问，使用 `aria-pressed`、`aria-checked`、`aria-expanded` 表达状态，焦点环
只在 `:focus-visible` 出现。

## 模型接入与扩展入口

模型接入管理 Codex 主 Agent、模型账号与 API 凭据；扩展管理 Skill 指令、MCP 工具和协作角色。角色负责一项任务，使用已接入模型，不重复登记账号。未实现的自动分派/OAuth 必须说明能力边界。旧 settings/partners 连接路由兼容到模型接入；角色使用 skills/partners。UI 交付需从 canonical 实际重建并分别验证 Web development、production preview 和 Desktop，确认加载资源身份及同状态画面，不能以其他 worktree 的源码改动代替生效证据。

通用模型选择只管理来源、供应商和型号，不混入批量数量或数据/隐私模式。图片节点的生成数量属于对应生成操作；已有任务与草稿参数仍按原数据契约保留。

## 喜欢、标签、搜索与数据管理

喜欢保留个人偏好；标签组织素材类别；资源库管理归档原件、来源与复用；存储管理实际数据位置、空间、缓存、备份与恢复；使用记录展示当前设备已保存任务的实际回执。功能入口与数据职责分别命名，不能用一个收藏页承载所有能力。

图片卡片的喜欢和标签位于选中卡片的顶部共享工具栏。喜欢和标签各有一个独立屏幕面板，固定屏幕尺寸且可自由拖动，不随画布缩放；两者可同时打开，分别关闭、回焦、搜索。位置是非敏感界面偏好，项目内容和编辑草稿按项目隔离。拖动把手不平移画布，窗口缩小时面板仍可找回。旧收藏入口映射“画布标签”，数据映射“收藏”标签。

全局搜索按全部、画布卡片、项目、已加载资源分类，并有类型/标签过滤；“已加载资源”只表示当前页已加载内容，不冒充完整归档。资源库的归档原件与设置中的存储统计分别核验。

## 服务商目录与 CLI

公共预设只提供品牌、协议、地址策略、官网、密钥/本地认证说明和接口文档。品牌不等于协议支持；通用文本协议按 [ADR-018](architecture/adr/ADR-018-provider-protocol-and-cli-execution.md) 显式保存，Gemini 预设前往独立 Google 配置。目录浏览不自动探测网络、调用模型或写凭据；检测仅请求模型列表，不把获取目录成功显示为生成已验证，密钥仍使用原凭据事务。

CLI 的安装/检测、本机登录、连接、模型与运行状态分别解释。检测版本/帮助、终端打开/退出和桥进程健康均不能显示为账号或模型已验证；安装、登录和桥管理由用户点击启动，取消/停止只作用于 KK 拥有的进程。Google 网站登录、Gemini CLI 登录与 Gemini API Key 不互借身份；Codex 继续是主 Agent。未验收的真实安装、账号登录、供应商生成与平台仍保留开放边界。
