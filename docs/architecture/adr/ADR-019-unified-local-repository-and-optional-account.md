# ADR-019：统一本地仓库、可选账号与手动加密同步

- 决策依据与授权范围：用户明确要求 Desktop/Web 均免登录可用、共用完整本地项目与素材库、关闭客户端窗口后网页继续使用，以及只有手动同步才上传产品数据；随后批准统一实施方案。
- 替代/被替代的 ADR：部分替代 ADR-008 的 Web 必须登录目标与 ADR-011 的 BYOK 延后限制；三端版本、Desktop→Web→Mobile 顺序、独立 Mobile 工程及真实链路双门保持有效。

## 背景和约束

现有 Web IndexedDB、Native 原生仓库及本机伴随服务各有实现，路径和部分资产格式不同，不能仅选择同一文件夹就宣称共仓库。Web 跨源访问回环服务还受到浏览器权限、Cookie 和安全上下文约束。强制登录、登录后默认上传，均与本次批准需求冲突。

现有快照为 CreationSnapshot version 2，写入有 revision/CAS，项目和素材有稳定 ID。用户数据、凭据引用与旧链接必须保留。旧快照不能因新增字段被丢弃，旧客户端也不能在不知道新字段时覆盖新数据。凭据不能进入项目包、明文浏览器存储、URL 或日志。

## 方案比较

| 方案 | 取舍 |
| --- | --- |
| 两端各存一份、同名自动合并 | 无法保证同一项目身份与并发保存，可能静默覆盖，拒绝 |
| 登录后默认云存储 | 改变隐私和本地优先语义，拒绝 |
| 统一格式、本机单写入协调、显式目录授权，可选账号与手动加密备份 | 复用现有存储契约并能保留冲突草稿，采用 |

## 决定

1. Desktop/Web 均可免登录本地创作；账号只提供用户主动启用的身份及同步能力。登录不上传项目、素材、聊天、API 配置或密钥。
2. 同机共享完整仓库，沿用现有快照、素材身份和任务语义；扩展统一格式、目录身份、跨进程锁和版本检查，不新建一套任务队列或配置系统。Web 独立本地模式与共享仓库之间须显式预检及导入，断线不隐式建立第二份项目。
3. 本机服务授权与 KK 账号授权分离，限定来源、设备、仓库和操作；禁止以宽泛 CORS、长期 URL token、任意绝对路径请求或开放凭据库替代授权。关闭窗口后，只要网页租约或任务仍需要，必要存储服务继续运行。
4. 项目生命周期和分组字段兼容扩展现有快照；软删除保留完整项目和资产引用。分组删除只解除归属。名称来源记录手动修改，自动命名不能覆盖。所有状态仍以真实写入回执为准。
5. 本地生成原件为主副本。目录更改不移动旧内容，只改变后续目的地，已受理任务冻结目的地。垃圾箱由用户主动清理，清理需可信完整引用闭包及锁内复核。
6. 只有网络设置中的手动同步操作处理用户选定内容：KK 保存所选配置与加密索引，用户云保存完整加密项目/组包。密钥与敏感元数据在客户端保护，服务器与云不拥有根解密密钥；设备会话、权限及临时聊天正文不进入备份。
7. Desktop 凭据仍由系统凭据库承载；Web 仅允许成熟客户端协议保护后的密文持久化，解锁密钥不随密文明文存放。具体密码认证、密钥封套及云协议在实施时经当前官方文档、安全测试和独立审查，不把加密算法名称当作整体安全证明。

## 迁移、恢复与退出

逐项兼容读取旧快照、配置及原件，统一格式变更须有迁移前预检和校验；未知格式、断连、离线、锁冲突或索引不可信时暂停写入，保留草稿与旧内容。项目包按用户所选项目/组冻结快照，恢复先暂存校验，再发布；冲突保留副本，不重提旧生成任务。错误回滚不能让旧客户端覆盖它不理解的新格式。

临时聊天无记忆读写、无正文持久化，作品仅保留必要文件元数据。项目垃圾箱、待归档任务及未知受理任务仍保留引用。物理删除与云历史清理不由本决定自动授权。

## 验证和接受条件

同机双端并发不覆盖、断连不分叉、关窗口网页可写、目录授权撤销和跨账号隔离须真实测试；匿名/登录未同步不上传须网络证据；备份须验证密文篡改、分卷中断、配额、CAS 冲突和新设备完整恢复。Desktop→Web 阶段门、精确提交独立审查和实际产物验收继续有效。开放状态见 TASK-KK-UNIFIED-20261015，ACCEPTED 不等于实现完成。
