# ADR-006：阶段计划与项目包的跨端契约

- 状态：ACCEPTED（技术决定；实现和发布状态以任务证据为准）
- 日期 / Task ID / Owner：2026-09-24 / TASK-ORCH-001 / root
- Intent / Spec / Plan：[编排交付包](../../changes/2026-09-23-agent-orchestration/intent.md)、[规范](../../changes/2026-09-23-agent-orchestration/spec.md)、[计划](../../changes/2026-09-23-agent-orchestration/plan.md)
- 决策依据与授权范围：用户要求继续修复竞品对齐任务中的遗漏、错误和冲突；该决定只同步现有阶段计划的本地存储与项目包边界。
- 替代/被替代的 ADR：无。

## 背景和约束

- 当前架构、代码/契约证据与问题：`CreationProject.stagePlans` 由前端归一化补入空数组。原生 `.kkproject` 严格白名单未接受该字段，Web/Rust 引用收集也未遍历阶段工作项；独立审查确认旧项目导出受阻、只由计划引用的素材漏打包。工作项 ID 若重复，按 ID 更新会同时改变多个工作项。
- 用户目标和不可改变的产品语义：已归档素材要随项目可恢复；人工审批后迟到执行结果不能倒退计划；失败不能伪装成成功导出。
- 平台、数据、安全、成本、性能和兼容约束：Web 与 Desktop 共用 `CreationProject` 形状；项目包格式版本仍为 1；不新增云端、凭据、付费调用或自动迁移。
- FACT / INFERENCE / UNKNOWN / CONFLICT：两端漏收素材和旧计划覆写已有复现；Desktop GUI 与真实 Provider 链路未验收。

## 方案比较

| 方案 | 优点 | 代价/风险 | 与现有架构的匹配 | 不选原因 |
| --- | --- | --- | --- | --- |
| 忽略 `stagePlans` 或导出时剥离 | 改动少 | 计划和仅由计划引用的原件丢失 | 违反完整快照导出 | 数据不可完整恢复 |
| 升级项目包版本并另建计划清单 | 可显式分版 | 增加迁移与双格式维护 | 当前字段为兼容增量 | 本轮无需改变包格式 |
| 在现有快照/项目包同步计划 schema 与引用 | 旧包可继续导入，新包完整保存计划 | 两端必须保持校验一致 | 沿用现有包和原件仓库 | 采用 |

## 决定

- 采用的方案与理由：`stagePlans` 保持可选，旧包无该字段仍可导入；新快照允许空数组，供应字段严格校验。计划级工作项 ID 唯一；重复 ID 在创建、归一化和 Rust 项目包校验处拒绝，避免按 ID 写入误伤其它工作项。
- 模块职责、依赖方向、公共接口：TS `stagePlanSchema` 定义本地计划形状和唯一性；Web `projectPackage` 与 Rust `project_package` 仅收集 schema 指定的素材引用；Rust `project_package_snapshot` 独立验证包快照。编排器工作项更新以 `expectedRevision` 和合法状态迁移提交，不暴露任意计划覆盖入口。
- Desktop/Web/Mobile 差异与降级：Web 使用共享 TS 包逻辑；Desktop 使用 Rust 原生 ZIP 和严格校验；Mobile 尚无独立项目包运行证据。
- 数据/schema、权限、凭据、日志边界：包版本不变，`stagePlans[].stages[].workItems[].assetId` 指向已归档原件；无新权限、密钥或敏感日志。
- 不在此次决定范围内的能力：真实生成驱动、计划 UI、MCP 工具注册、Tauri GUI 发布验收。
- AI 自主技术判断与需用户决定的产品事项：这是现有数据完整性和审批语义的修复，无新的产品选择。

## 迁移、恢复与退出

- 分阶段兼容与数据迁移：无字段的旧项目/旧包保持可读取；归一化后的空数组可以导出。重复 ID 的候选计划不被视为有效可写入数据，已存在的异常快照需保留原件并单独诊断，不自动改名或覆盖。
- 并发、失败、取消、离线、重启/损坏恢复：工作项以当前 revision 写入；迟到结果返回冲突且不写入。包校验失败不创建目标包或恢复目录；离线行为不变。
- 备份/校验/回滚或补偿：项目包原件和快照完整往返测试覆盖，失败保持源仓库；回滚通过任务分支 PR，不能删除用户项目。
- 运行监控、阈值与费用上限：计划最多 64 条、每计划最多 32 阶段、每阶段最多 128 工作项；无外部费用。
- 退役/替代/导出路径：继续使用 `.kkproject` 导出/导入；后续若改变包格式需新 ADR 与迁移测试。

- 对应测试、运行态、故障注入与恢复证据：Node 计划/项目包回归、Rust 包导出/导入和重复 ID 拒绝、全量 Node/Rust、浏览器回归；见[验证记录](../../changes/2026-09-23-agent-orchestration/verification.md)。
- 独立 review 与 source SHA：旧 head `67ff18fb7633beba5a86dfd1bb6be066880a2580` 复审发现重复 ID 问题；修复后 SHA 的复审待更新。
- 遗留风险、账本任务：真实媒体、UI 审批、MCP 注册与 Desktop GUI 仍按 TASK-ORCH-002/003 和后端账本项追踪。
- ACCEPTED 的技术依据；若需用户决定则引用真实授权：现有用户数据完整性与审批约束要求跨端同步；本决定在用户继续修复授权内，不代表产品验收。

ACCEPTED 不等于实现或发布已完成。已接受决定如需改变，新增 ADR 并标注替代关系；纠错追加勘误，不抹去历史。

## 2026-09-26 身份唯一性勘误

原决定只约束工作项 ID，遗漏了同样按身份更新的阶段 `index` 与项目内计划 `id`。前端计划 schema 现在拒绝重复阶段索引，项目读取只保留同 ID 的首个有效计划；Web 项目包的无损校验拒绝因此会丢失条目的导出/导入。Rust 项目包独立拒绝重复阶段索引或计划 ID，失败时不生成目标包。外部异常快照的原件仍须保留以供诊断，不自动改名或覆盖。该勘误不改变包版本或已接受的跨端完整性原则。
