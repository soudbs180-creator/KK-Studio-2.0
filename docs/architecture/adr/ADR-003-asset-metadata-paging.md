# ADR-003 素材列表元数据分页与原件按需校验

- 状态：Accepted，2026-09-21；TASK-PERF-ASSETS-001 / TASK-MAIN-CLOSE-002。
- 授权：用户要求完成未完成的性能与 UI 检查；这是授权范围内的技术决策。

## 问题与选择

此前素材列表逐项读取原图并构造 data URL，列表大小决定初次 IO 和内存。保留 Desktop 原生文件仓库和 Web IndexedDB 两个既有存储边界，统一将列表接口改为有界元数据页：UI 每页 40，接口最多 100。可见图片串行读取、校验并生成最大边 320px WebP，内存缓存最多 24 项；详情/导出/重绘仍校验原件。

不采用启动时预读全部原件；那会保留原瓶颈。暂不引入永久缩略图数据库，因为其一致性、删除与迁移需要独立验收。新增逻辑属于现有 creation asset repository，未建立第二套存储。

## 兼容、失败与回滚

IndexedDB 数据库版本和原件 Blob 不变；新写入 metadata 去除 preview，旧带 preview 记录仍可读取。列表返回值不再承诺预览字段，调用方已同步。Rust 完整 list 校验保留，新增 list_page 只检查 metadata 与原件路径/大小边界，实际读取仍检查 SHA；列表不再证明每份原件字节有效。

Web 读取在 bytes 之前绑定请求 ID、metadata ID、SHA 前缀、MIME 和大小，再检查完整 SHA。损坏、缺失、错身份和解码失败明确报错/重试，取消或切换不提交迟到 UI。原件无迁移或删除，回退对应提交可恢复旧读取路径；旧读取器可从 Blob 重建预览。

## 证据和限制

125 条约 280MiB fixture 的分页、末页搜索、0 次列表原件读取、缩略图尺寸、详情原件 SHA，以及 Rust 全量/分页/临时文件/丢件回归均通过。三模式运行证据见 main-close-002/verification.md。

单件原件 IO/哈希已开始后不可被 AbortSignal 抢占；单件图片仍短时持有原始字节与 Base64。重读保守保留已有缓存条目，外部删除在实际读取时报错。永久缩略图与会话/画布大快照继续由 PERF-001 跟踪。
