# ADR-025：Mobile 12ai 原件返回与视频查询恢复

- 状态：ACCEPTED；实现、发布和真实验收以交付包为准。
- 日期 / Task ID / Owner：2026-10-18 / TASK-MOBILE-12AI-001 / root。
- 依据：[Intent](../../changes/2026-10-18-mobile-12ai/intent.md)、[Spec](../../changes/2026-10-18-mobile-12ai/spec.md)。
- 不替代既有 ADR；编号 024 已在并行主仓任务登记，本次不复用。

## 背景和约束

真实 12ai 图片 POST200 后，远端图片 URL 缺少跨域许可，手机网页无法读取原件字节；已有任务保持 unknown。视频目前未接入，素材播放不等于生成。用户授权按官方文档补齐并上线，但要求保护现有数据与可回滚版本。

凭据仅安全库或请求内存，不能放入 URL、快照、项目备份或日志。不得静默换提供方地址，不依赖未经文档确认的上游幂等或退款。旧版快照验证采用严格字段集合，新增字段会破坏回滚后的可读性。

## 方案比较

1. 直接显示远端 URL：不能证明原件已保存，刷新可能失效，拒绝。
2. 新增通用服务器取图代理：引入服务器、权限、SSRF 和流量边界，本次没有必要，拒绝。
3. 按提供方协议取原件并复用本机仓库：图片同步返回 base64；视频提交任务、持久 ID 后只查询和下载。采用。

## 决定

- 仅对用户明确配置的已确认 12ai HTTPS origin 和官方根路径 `/v1`，同步图片请求 `b64_json`。通用兼容接口保持原契约，不改地址或传递 Key 到新主机。
- 文本保留当前受支持的单条 prompt/SSE，官方可选字段不为“参数齐全”而强加。
- 视频按官方明确模型 ID 的基础文生配置接入；不支持纯文的模型禁用。统一异步任务与 Sora 的端点、状态、下载格式分别处理，不虚构取消/content 接口。
- 复用已有 `kind=video`、`protocol=openai-compatible` 与 `providerRequestId` 保存远端任务 ID；不新增持久字段或新 schema，不持久远端 URL 和访问参数。Key 重填仍走原连接保存策略。
- 收到远端 ID 立即持久，成功后才开始查询；回执写失败仅恢复已有 ID，不发起第二次生成。刷新后由用户显式查询；仅原连接 ID、捕获 baseUrl/协议一致时可用当前重新填写的 Key 恢复。导入/还原的只读回执不查旧远端任务。
- 停止轮询不宣称取消生成或退款；未知受理不自动重发。下载、签名、大小、原件 readback/hash 和槽位归档实际完成后才能标成功。
- 继续使用既有 16MiB 单原件上限并显示限制。跨域原件请求不携带提供方 Key；重定向拒绝，安全 URL 与实际流量有界。Sora 的同源 content 兼容路径只按官方文档使用。

## 迁移、恢复与退出

没有数据清空、迁移或存储身份改变。新任务与素材只使用旧版已接受字段；回滚版本可读取资料，旧 UI 不能执行的视频仍安全拒绝。发布沿用 current/唯一 previous 的原子静态切换，不改业务数据库。完整冻结回执和跨版本读取检查作为放行证据。

若视频原图 CORS、超限或连接失败，保留远端任务 ID、草稿与已归档原件，允许显式 GET 核对，不能用重新生成代替下载。真实图片复验失败保留单次收费事实，不在后台无限重试。

## 验证和接受条件

图片返回格式及域名边界、已有文本/SSE、视频请求体与状态、重复提交/取消/超时、持久失败、刷新和换 Key 边界、只读回执、原件伪 MIME/超限/跨域无 Key、旧版读取、手机入口与完整质量门禁均需证据。fixture、Hosted、真实 Provider、实体设备、实际账单与用户验收分别记载。正式发布后单张图片自动归档和刷新下载字节一致，才接受图片闭环。
