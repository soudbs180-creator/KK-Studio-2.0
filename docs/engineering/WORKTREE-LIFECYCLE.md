# Worktree lifecycle

Worktrees are short lived task checkouts. The only approved shared location on this machine is `D:/kk-studio/.worktrees` (override with `KK_WORKTREE_ROOT` for another checkout). The primary repository, the current checkout, external worktrees, dirty worktrees, locked worktrees, and worktrees with an active ledger task are protected. The policy counts existing worktrees and generated bytes before a new checkout is created.

The 2026-10-09 cleanup audit found 47 registered worktrees, with 24 active in the approved root. Sixteen clean checkouts whose ledger branches were already `DONE` were removed while their branches and commits were retained. Generated dependency/build directories were reclaimed first; the remaining dirty, nested, external, or unregistered worktrees stay protected for owner reconciliation. The current counts are always read from [`worktree-reclamation.json`](../governance/worktree-reclamation.json) and [`workspace-inventory.json`](../governance/workspace-inventory.json), not from this paragraph.

The default limits are four active worktrees and 20 GiB of generated content. They can be changed for a controlled environment with `KK_MAX_ACTIVE_WORKTREES` and `KK_MAX_GENERATED_BYTES`; a path outside the allowed root is always rejected. A requested branch is reused when it already has a registered worktree. Creating a worktree never runs `npm install` automatically; dependency installation remains an explicit command in the selected worktree.

Run the creation gate before creating a checkout:

```text
node scripts/governance/worktree-policy.mjs --check-create --branch=codex/TASK-EXAMPLE
```

The command exits non-zero when either budget is exceeded, the branch is missing, or the requested location is outside the policy root. It reports `REUSE_EXISTING_BRANCH` when the branch already has a worktree.

Reclamation defaults to an audit. It writes a uniquely named immutable plan under `docs/governance/` and performs no deletion:

```text
npm run worktree:reclaim
```

`docs/governance/worktree-reclamation.json` is a stable pointer containing the latest plan ID and summary. The pointed plan file is immutable; a later audit creates another plan instead of replacing it.

Generated directories are candidates only when their real path remains inside the worktree, no symlink or reparse point is present, no tracked file is underneath, and the worktree is clean, unlocked, current-task free, and not an evidence or recovery path. Ignored evidence is preserved. A worktree can be removed only when every ledger entry for its branch is `DONE` and its head is reachable from `origin/main` or `main`, or a verified recovery bundle is recorded.

An immutable plan contains a deterministic SHA-256 inventory for each explicitly approved candidate. Before applying it, the operator must name the plan and candidate IDs; the implementation rechecks containment, locks, task state, and the source inventory immediately before removal. A changed file, missing inventory, unknown candidate, or failed recovery check retains the path. Each apply writes a unique `worktree-reclamation-result-*.json` record, so prior plans and actions are never overwritten.

```text
node scripts/governance/worktree-reclaim.mjs --apply \
  --plan=docs/governance/worktree-reclamation-plan-<plan-id>.json \
  --approve=<candidate-id>[,<candidate-id>]
```

Do not archive or remove a known active task automatically. If a task must be retained for recovery, create and verify a durable Git bundle or external recovery archive before proposing its checkout for removal.
