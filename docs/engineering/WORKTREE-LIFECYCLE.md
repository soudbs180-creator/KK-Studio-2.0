# Worktree lifecycle

Worktrees are short lived task checkouts. The only approved shared location on this machine is `D:/kk-studio/.worktrees` (override with `KK_WORKTREE_ROOT` for another checkout). The primary repository, the current checkout, external worktrees, dirty worktrees, locked worktrees, and worktrees with an active ledger task are protected. The policy counts existing worktrees and generated bytes before a new checkout is created.

The 2026-10-10 audit records 54 registered worktrees: 25 under the approved root, 26 nested under the primary checkout, 2 external Codex checkouts, and the primary checkout. No whole checkout is currently eligible for removal because every candidate is dirty, not main-reachable, active, or lacks a recoverable task record. The duplicate AI Gateway checkout `TASK-AI-GATEWAY-001-doubao-p1` remains protected; its implementation was selectively integrated into the primary branch, while the source branch stays available for reconciliation. Fourteen generated dependency/build directories were previously removed from the clean concurrency worktree, and the new audit removed one additional `.tmp` directory (27 evidence files, 4.05 MB) after SHA inventory and recovery backup to `D:/kk-studio/.verification/governance/TASK-VERIFY-CONCURRENCY-002-tmp-4a990be8c98c54bd`. The current counts are always read from [`worktree-reclamation.json`](../governance/worktree-reclamation.json) and [`workspace-inventory.json`](../governance/workspace-inventory.json), not from this paragraph.

The default limits are four active worktrees and 20 GiB of generated content. They can be changed for a controlled environment with `KK_MAX_ACTIVE_WORKTREES` and `KK_MAX_GENERATED_BYTES`; a path outside the allowed root is always rejected. A requested branch is reused when it already has a registered worktree. Creating a worktree never runs `npm install` automatically; dependency installation remains an explicit command in the selected worktree.

Run the creation gate before creating a checkout:

```text
node scripts/governance/worktree-policy.mjs --check-create --branch=codex/TASK-EXAMPLE
```

The command exits non-zero when either budget is exceeded, the branch is missing, or the requested location is outside the policy root. It reports `REUSE_EXISTING_BRANCH` when the branch already has a worktree.

Reclamation defaults to an audit. It writes a uniquely named immutable plan under `docs/governance/` and performs no deletion:

```text
npm run worktree:reclaim
```

`docs/governance/worktree-reclamation.json` is a stable pointer containing the latest plan ID and summary. The pointed plan file is immutable; a later audit creates another plan instead of replacing it.

Generated directories (`.tmp`, `node_modules`, `dist`, test output, Rust targets and agent-runtime output) are candidates only when their real path remains inside the worktree, no symlink or reparse point is present, no tracked file is underneath, and the worktree is clean, unlocked, current-task free, and not an evidence or recovery path. Ignored evidence is preserved. A worktree can be removed only when every ledger entry for its branch is `DONE` and its head is reachable from `origin/main` or `main`, or a verified recovery bundle is recorded.

An immutable plan contains a deterministic SHA-256 inventory for each explicitly approved candidate. Before applying it, the operator must name the plan and candidate IDs; the implementation rechecks containment, locks, task state, and the source inventory immediately before removal. A changed file, missing inventory, unknown candidate, or failed recovery check retains the path. Each apply writes a unique `worktree-reclamation-result-*.json` record, so prior plans and actions are never overwritten. Large file-level recovery inventories may be kept in `D:/kk-studio/.verification/governance/` rather than committed to the source repository; the committed apply result and immutable plan pointer remain the audit entry points.

```text
node scripts/governance/worktree-reclaim.mjs --apply \
  --plan=docs/governance/worktree-reclamation-plan-<plan-id>.json \
  --approve=<candidate-id>[,<candidate-id>]
```

Do not archive or remove a known active task automatically. If a task must be retained for recovery, create and verify a durable Git bundle or external recovery archive before proposing its checkout for removal.
