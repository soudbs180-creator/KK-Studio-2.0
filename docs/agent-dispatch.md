# 谁来干活？—— KK Studio 的 Agent 调度，用大白话讲清楚

> 状态：这是一份「说明书先行」的用户向说明。下面讲的调度办法正在落地建设中，本文先把规矩讲清楚，会随实现一起更新；文中提到的几个小零件也还在做，不代表此刻已经全部上线。
> 读这份不需要懂编程。文末有一节给好奇的人看技术名字，普通读者跳过去也不影响理解。

## 0. 先记住一句话

**一个聪明但贵的「总指挥」只负责动脑规划，一群便宜又能干的「小工」负责动手干活；谁合适、谁还有额度，就先派给谁；谁被限流了就先歇一会儿，活儿不会因此卡死。**

可以把它想成一支装修队：

- **包工头（主 Agent）**：脑子最好、工钱最贵。他不来刷墙、不铺地砖，只干一件事——听你要什么，然后画图纸、拆活儿、拿主意、处理疑难杂症。
- **工人（子 Agent / 其它模型）**：各有手艺，有的会画图、有的会剪视频、有的便宜又快。真正动手的是他们。
- **派工员（调度器）**：拿着包工头拆好的一张张工单，去花名册里挑一个当下最合适、还有额度的工人来接。

一句话概括这套规矩：**主 Agent 只规划、子 Agent 干活、有额度先上**。

## 1. 三个角色，先认清

| 角色 | 大白话叫什么 | 干什么 | 不干什么 |
| --- | --- | --- | --- |
| 主 Agent | 包工头 / 总指挥 | 听懂需求、把大任务拆成一张张「工单」、做决策、啃最难的那部分推理 | 默认不亲自去生图、生视频、合成语音 |
| 子 Agent / 其它模型 | 干活的工人 | 按工单把活真正做出来，做完把结果交回去 | 不替你拍大方向、不管全局 |
| 调度器 | 派工员 | 给每张工单挑人、盯额度、谁掉链子就换下一个 | 自己不干活，也不改图纸 |

为什么这么分？因为**主 Agent 通常更贵、更偏「会想」，而且往往没有生图、生视频这些手艺**。让它包办一切，既费钱，又干不了它不擅长的活。让它专心规划，把具体活儿派给更便宜、更对口的通道，是又省又稳的做法。

## 2. 你说一句话之后，发生了什么

比如你说：「把这张照片扩成海报，再配一段旁白。」

```
你的需求
   │
   ▼
① 主 Agent（只规划）：拆成工单
     · 工单 A：把图扩成海报（要「扩图」手艺，可能要花钱）
     · 工单 B：配一段旁白（要「语音合成」手艺）
   │
   ▼
② 调度器（派工）：给每张工单挑人
     · 会这手艺 ∧ 状态正常 ∧ 还有额度 ∧ 没在冷却
     · 挑最合适的那一个
   │
   ▼
③ 子 Agent / 能力通道：动手干活
     · 干成了 → 交结果
     · 撞到限流 / 额度用完 → 标记一下，立刻换下一个候选
   │
   ▼
④ 结果回到主 Agent：只收「做完了、大致如何」的摘要
   │
   ▼
⑤ 主 Agent 汇总，用一句话回你
```

关键点：**包工头自始至终没自己去刷墙**。他只拆活、派活、收尾、汇报。而且收回来的只是结果摘要，不是一堆内部数据——密钥、凭据这些东西不会顺着这条路流回主会话，也不会被写进日志。

## 3. 四条规矩，一条条说

### 规矩一 · 主规划：主 Agent 只动脑，不动手

主 Agent 的活儿是「想」：把你的口语拆成清楚的步骤、决定先做什么后做什么、遇到拿不准的难题自己啃下来。

按默认规矩，**它不会直接去跑生图、生视频、合成语音这类活**（`image.*` / `video.*` / `audio.*`）。除非花名册里明确写了它确实会这门手艺、并且你手动强制，否则这类工单一律派出去。这样它贵的那部分算力，全花在刀刃上。

> 对应到设计里的说法：规划与疑难推理（`text.plan`）留在主 Agent；同一张工单一次只交给一个人做，几张互不依赖的工单才并行开工。

### 规矩二 · 子执行：谁会这活儿，谁干

每张工单都写清楚「要什么手艺」。派工员只从**会这门手艺**的通道里挑人。要扩图就找会扩图的，要配音就找会配音的，不会的连候选名单都进不去。

这就是「主 Agent 往往没有生图/视频能力」的解法：**缺什么手艺，就调有这门手艺的别的 Agent 或模型**，而不是让主 Agent 硬扛。

### 规矩三 · 额度过滤：有额度、又合适的，先上

「有额度先上」不是一句口号，是两步：

1. **先过滤**，把不合格的划掉：手艺不对口的、状态坏掉的、已经标了「额度用尽」的、还在冷却中的——都不派。
2. **再排序**，从剩下的里挑靠前的：你手动置顶的优先 → 明确还有额度的优先 → 更便宜的优先 → 响应更快的优先 → 本机硬件更合适的优先。

于是通常的结果就是：**还能用、又对口、又便宜的那个，先被派上**；贵的、快没额度的排在后面当备选。

### 规矩四 · 限流冷却：被限了就换人、歇一会儿，不卡死

上游服务偶尔会回一句「太快了 / 额度到顶了」（常见的 `429`、额度用尽、余额不足、鉴权失败等）。老做法是直接报错、整个任务断掉；新规矩要让这件事**不打断你**：

1. 先把这些五花八门的报错**翻译成统一的信号**（是「额度用尽」还是「请求太快要等一等」）。
2. 在花名册上给这个通道做个记号：**「额度用尽」** 或 **「歇到某个时刻」**（冷却）。
3. 调度器**立刻顺着名单换下一个候选**，工单继续跑。
4. 界面给你一条不打断操作的轻提示，比如「某某额度用尽，已改走另一个通道」。
5. 等额度恢复的时间到了，或你手动点一下「重新探测」，这个通道再回到可用状态。

这样，**某一个通道没额度，不等于整个任务失败**——主会话照样能规划、能继续，只是换了个人干活。

## 4. 「有额度先上」具体怎么挑

把规矩三、四合起来，派工员对每张工单做的事其实很朴素：

- **能派的条件**：手艺对得上 ∧ 状态不是「坏」 ∧ 没标「额度用尽」 ∧ 现在已过冷却时间。
- **排队顺序**：手动置顶 → 还有明确剩余额度 → 更省钱 → 延迟更低 → 本机硬件推荐。
- **领第一个来干**；要是它失败或撞到 429，就给它做记号（额度用尽 / 冷却），**接着试名单里的下一个**。
- **万一整张名单都没人能接**：主 Agent 不会硬着头皮自己生图/生视频，而是老老实实告诉你「现在缺什么、要不要换个模型或补一下凭据」，需要花钱或补凭据的还会先弹个确认。

## 5. 花钱的活儿，先过一道预算门

有些工单是要花钱的（付费生成）。这类活在派出去之前，会先过一道**预算门**：

- **预算之内**：自动放行，AI 直接干，不打扰你。
- **超过预算**：先弹出来让你确认一次，你点头才继续。
- **预算设成 0**：等于「每一笔都要问我」，次次确认。

所以你不用担心「不知怎么就被扣钱了」——花钱这件事有一道看得见的闸。

## 6. 背后有哪几个小零件（给好奇的人看）

上面这套规矩，落地时主要靠四个小零件配合。它们都计划放在 `src/features/agent-dispatch/` 这一处，名字分别是：

| 名字 | 大白话职责 | 对应上面哪一节 |
| --- | --- | --- |
| `agentRegistry` | **花名册**：登记有哪些 Agent / 模型、各会什么手艺、贵不贵、还有没有额度、是不是在歇、健康不健康。主 Agent 只有一个「当前」指针，其余自动进工人池 | 规矩二、三、四 |
| `quotaSignals` | **报错翻译官**：把各家不同的「429 / 额度用尽 / 欠费 / 鉴权失败」归一成统一信号，再写回花名册。只处理信号，绝不把密钥带出来 | 规矩四、限流冷却 |
| `budgetGate` | **看预算的**：派发付费工单前查一下预算，决定「自动放行」还是「先问一句」 | 第 5 节预算门 |
| `dispatcher` | **派工员**：拿着工单去花名册挑人、排序、失败就换下一个；主 Agent 不进入生图/视频的候选名单 | 第 2、4 节 |

四者的关系：**花名册**提供「有谁、谁能干、谁还有额度」，**报错翻译官**负责把额度状态改准，**预算门**管住花钱，**派工员**把前面三份信息合起来做决定。

> 说明：本节只是把这几个零件「要干什么」讲清楚，**本文不改动任何代码**；文中也不含任何真实密钥、令牌或账号凭据。凭据只以「引用」的形式存在凭据库里，调度过程不接触明文。

## 7. 你可能想问

- **主 Agent 这么强，干嘛不让它全干？** 它更贵、偏「会想」，而且常常没有生图、生视频这些手艺。让它专心规划最划算。
- **某个额度用完了，我会不会看到一串报错、任务直接黄了？** 不会。系统会标记一下、换个人接着干，只给你一条轻提示；到点还会自动恢复。
- **我会不会莫名其妙被扣钱？** 花钱的活儿先过预算门，超预算会先问你；预算设 0 就每笔都问。
- **我的密钥安全吗？** 密钥存在凭据库里只留引用，不进日志、不顺着结果回灌给主 Agent，这份文档里也不放任何真实密钥。
- **我能自己指定用谁吗？** 能。你可以手动把某个通道置顶、或切换「当前主 Agent」，其余的会自动进工人池。

**一句话总结**：主 Agent 当包工头只画图纸，子 Agent 当工人真干活；派工员永远先把活派给「手艺对口、还有额度、又便宜」的那个，谁被限流就先歇着换下一个，花钱的活儿先过预算门问一声——这样既省钱、又不掉链子、也不会因为你某一个额度用完就整个卡死。
