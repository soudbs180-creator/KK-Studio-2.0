# 输入组件契约 · DS 1.3

## 来源与问题

Ardot 728457371665311 / PDF 的颜色与基础控件规则沿用 DS1.1 校正。2026-09-23 重新读取 Figma `0nU0A7pq6eyjwfwm1TtWkO` 节点 `407:29310`：圆角20、文本上方/操作下方、保留原资产。该静态稿文本10px、64px文本区与56px固定间隔、22/24px控件不能直接承载新增参数或触屏使用，作为本次修订明确的工程补充。

旧文档只定义单行32px输入；旧源码把附件绝对定位在固定间隙中，三档另叠加尺寸规则，textarea又继承全局方形焦点。现有测试通过不等于这些视觉问题被用户接受。

## 组件与布局

- 普通单行字段：继续使用 `.ui-input`，r10、32/40/44px；搜索图标和字段边界由现有组件拥有。
- 创作输入容器：首页与对话共用 `.composer-surface` 和 `ComposerTextarea`，bg-input、1px border-control、r20；只在文本聚焦时外框显示2px focus-ring，内部textarea透明无第二层边框；按钮仍有独立键盘焦点。
- 文本区 → 可选附件 → 可选型号参数 → 操作栏 → 首页生成选项，全部正常文档流。没有附件就不产生空占位。附件换行、移除按钮可见；型号说明长文本换行，不覆盖输入或动作。
- 桌面文字14/20，触屏16/24；起始3行，随内容增长至8行，再在文本区内滚动；短屏≤600px保留2行至4行。草稿与中文合成不因增长或切档丢失，不新增Enter提交语义。
- 桌面操作32px、主图标20/辅助16；触屏（宽≤1200）操作44px，图标仍20/16，不放大资产填满命中区。短标签不拆行，模型弹性扩展/单行省略并保留title。
- 宽首页操作一排；窄首页/触屏对话固定两排：第一排模型、Skill、插件；第二排附件、语音靠左，权限、发送靠右。批量/隐私单独一排等宽弹性列，不混进模型组。
- 电脑对话保持470px面板和现有外部位置，首页保留现有外宽约束。世界坐标节点不消费此契约。
- 菜单按整条操作区域避让（首页含批量/隐私行），优先在足够的下方或上方空间展开，必要时限高并内部滚动；滚动、尺寸和内容变化后重算，不能把弹层clamp到触发按钮上。≤600px短窗口中电脑对话也要承接纵向滚动，动态组合内容不能被工作区裁切成不可达控件。
