## 避免功能重复的执行规则

1. 每次改动先查 feature registry 和 task ledger；已有能力补原条目。此次只更新 TASK-ORCH-002 与 FEAT-030，没有增加同类 feature/task。
2. 多入口可以保留，但共用命令、状态和资产身份。任务浮层/工作台、Skills 输入框/设置页均是同一状态的视图，不是待删除的重复功能。
3. 重试只覆盖确定失败项。unknown、submitted、已归档输出不重新收费提交；UI 审批不能替代供应商提交审批。
4. 不以类名、适配器、按钮或空返回值认定能力完成。Comfy 事件无消费者、PluginAi 空 URL/images、plan_replan 摘要占位均记作未闭环。
5. 功能状态只在原登记处维护；本文是比较与实施理由，不建立第二份功能状态表。

## 后续优先顺序

第一项 TASK-ORCH-002 已进入本轮实现和验证。随后先做 TASK-ORCH-003 的图片/文本绑定及 unknown 状态映射，同时在 T5 复现并修复原生连接/健康/恢复差距；再扩 BACKEND-MEDIA-001，统一格式白名单和异步输出。Comfy 在 T6 内补运行消费与执行快照；MCP/Skill/插件执行在 BACKEND-MCP-AUTO 内推进。3D/剪辑应先保证现有插件结果回传、版本与资产溯源，再扩专业编辑能力。

TASK-ORCH-003 账本依赖完整 BACKEND-MEDIA-001，而其验收先要求图片/文本闭环。后续开工应明确拆分验收范围并更新原依赖说明，不能静默绕过，也不必为了图片/文本先完成全部视频/音频。外部 Provider、GPU、MCP、正式发布和 Mobile 均需各自的运行证据；本轮不会提升这些未验证能力。
