## 用户原意

用户希望当前 KK 界面遵守现行设计规则，新增入口有实际可用的操作，且 Web 与桌面显示的是经过验证的同一批能力。此前用户明确希望 Codex 为主 Agent，逐步接入 WorkBuddy、豆包和设计素材服务；本轮先检查已有界面与交互，避免把显示出来的入口误当作后端已接通。

2026-09-25 补充：用户给出 Figma `483:695`、`483:753`、`483:588`、`483:1042` 与六条浏览器批注，要求先把组件尺寸/状态写成准确规则，再改首页输入、搜索分类高亮、底栏空白与对话开关的持久/水平对齐行为。Figma 连接恢复后四节点已实际读取。

用户随后要求将同一套新 UI 规则应用到其余页面。本轮从根工程承接 `UI_INDEX / UI_RULES / UI_ARCHETYPES / DESIGN_TOKENS` 候选规范，并扩展到资产、提示词、设置分类及任务工作台的运行截图核对；规范导出与现行 shell/token 的冲突必须如实记录。

## AI 工程转译

以 Design System 1.3 和当前实现为依据，检查首页、画布、对话、设置的尺寸、图标、窄屏、焦点、菜单、入口路由与项目状态。修复有运行证据的偏差，使用真实浏览器回归。区分孤立演示画布、用户新建空白项目和 Agent 测试项目；测试必须描述实际产品语义。记录当前桌面产物身份和无法验收的服务边界。

## 目标与边界

- 预期结果：新界面与操作在桌面、平板、手机宽度下可读、可触达，入口指向对应内容；现行浏览器回归通过。
- 包含范围：首页创作控件、画布和侧栏尺寸、设置分类和扩展标签、密钥显示控件、项目与 Agent 测试入口。
- 独立后续任务：WorkBuddy、豆包真实接入，共享记忆、自动模型调度、真实第三方授权与额度管理仍按现有 Agent/功能账本推进；本轮不得因可见入口升级为 REAL。
- 平台：Web production preview；Desktop release 需单独重建和验收，浏览器窄屏不等于原生移动端。

## 假设、风险和决策

- FACT：根工程有未提交并行改动；本任务在独立 worktree 实施。当前桌面快捷方式指向已不存在的旧目录；旧 EXE 的时间早于本轮 UI 变更。
- FACT：Design System 1.3 规定三档布局、语义 token、创作输入结构与 UI 运行链路验证。
- INFERENCE：旧桌面与当前网页的差异主要受构建身份和入口影响；需要新 Desktop release 复验才能确认最终桌面效果。
- FACT：Figma 四节点由恢复的连接实际读取并保存同态截图。用户最终视觉验收和外部厂商真实登录调度仍 UNKNOWN。
