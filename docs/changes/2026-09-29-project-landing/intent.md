# Intent：项目落地与分支收敛

## 原意

继续处理未完成任务。已有 MiniMax Design 与 Kaworkai 两组竞品研究，下一步要把可落地能力并入项目，核对已经做过的优化是否真正加载，检查 UI 是否出现回退，并把已完成分支收敛到最新主线。

## Outcome

在最新 `origin/main` 基线上得到一个可审阅的项目候选：竞品研究对应的本地能力、当前 UI/画布改动与远端已合入能力同时存在；未完成或外部受限能力继续保持真实状态，不用测试或占位页面冒充完成。

## Scope

- 保存并审阅当前工作区的 UI、Figma 治理和 Kaworkai 画布改动。
- 将 `origin/main` 的 image compare、平台版本和 local companion 等已合入能力纳入候选。
- 复核首页、对话、设置、侧栏和画布在 390、1099、1920 宽度的实际加载、几何和交互。
- 修复合并冲突、格式/类型/运行回归和证据与源码不一致的问题。
- 对已完成且可验证的本地能力更新任务/功能证据，并明确保留的 PARTIAL/BLOCKED 项。

## Non-goals

- 不复制竞品的品牌颜色、CSS 或付费/积分流程。
- 不虚构真实 Provider、ComfyUI、云端账号、积分、生产部署或桌面安装验收。
- 不删除、重置或覆盖当前工作区中未归档的用户改动。

## Acceptance

1. 候选分支包含最新 `origin/main`，且 Git 树、依赖和入口版本一致。
2. 首页/对话/设置/侧栏/画布在真实 Vite 运行态加载当前源码 bundle；桌面端受影响路径至少完成静态检查。
3. 受影响的 typecheck、unit、lint/UI-check、format、build 与浏览器回归有新鲜证据；已知 fixture 或外部条件失败单独记录。
4. UI 只保留能改善实际体验的改动；固定空白、遮挡、不可达按钮、重复入口和未接服务入口必须修正或明确禁用原因。
5. 分支/任务状态与实际 head、验证结果和功能卡一致，未完成项不被标记为 DONE/REAL。

## Failure boundaries

- 合并后出现同一文件的行为冲突时，以最新主线的真实服务/存储契约为基线，再保留 UI 层的可验证改动。
- 浏览器加载旧 bundle、错误端口或旧 checkout 时，不能把截图当作当前源码证据。
- 外部凭据、远程服务或生产权限缺失时，保留 BLOCKED/PARTIAL，不通过本地 mock 推进状态。
