# 验收与存储保护规格

采用现有模块与 StoragePort，保留 Native、Companion、Browser 的实际格式边界；不做原地跨格式转换。备份恢复必须同时校验来源与所有将覆盖的现存资产记录，准入失败不得改变主快照、快照备份、资产记录或原图字节。

Native v1 或未来封装返回 `SNAPSHOT_UNSUPPORTED`；未知资产结构、坏 JSON 或无法读取的目标返回 `IO`。沿用现有 `CompanionProtocolError` 和回滚流程，不放宽 schema、跳过断言或修改基线。

五阶段完成条件：

1. 实际源码指纹绑定本地门禁、构建/安装收据及 UI 证据，分别列出未验证项；旧 UI-004 704 次执行不升级为全页六态或像素验收。
2. 保护旧资料的真实入口通过回归；Browser→Companion 与 Native 内迁移分别验收，跨格式显式导入与 Native HTTP 读写没有接线时保留未完成。
3. Agent 公告逐条对应锁文件和运行拓扑；插件生产门保持关闭，legacy 宿主权限明确；vendor 当前指纹与历史来源身份分开，未知上游 SHA 不猜。
4. 仅在授权和环境就绪后验证图片、音视频、成本回执与恢复；当前不启动真实计费请求。
5. 先采缩略图、打开时间与内存基准，再决定性能修改；本轮不凭推测添加虚拟列表或 workspaces。
