# 从 KK 使用已登录 Codex

在工程根目录使用 Node 24：

```powershell
npm run dev:agent
```

打开 `http://127.0.0.1:1421/`，创建或进入项目。启动器同时运行 Agent（17381）和固定端口 Vite，KK 通过同源桥接自动连接，Token 只由后端注入。仅管理它自己创建的子进程；端口被占用时报错，不另选端口。

使用 vendor 中官方 Codex CLI/app-server 与当前用户的现有登录。不必打开 Codex 图形窗口，但本地服务需要运行。未登录时通过官方 Codex 登录；KK 不读取或保存登录令牌。本轮尚未将启动器打入 Tauri 安装包。

手动方式仍保留 `npm run agent`（17371）：设置 → 网络填写本机地址和启动时 Token。Token 只在当前页面内存，刷新后需重新提供。此方式与 dev:agent 不需要同时运行。

## 对话与画布

- 默认项由 Codex 负责规划、优化提示词和调用画布 MCP。例如“读取画布，创建一个标题为产品文案的文本节点”。
- 调用已配置 API：“先优化提示词，再用 KK 当前选中的图片 API 生成一张”。任务记录显示真实受理/执行，API Key 留在 KK。
- 账号内置生图：“使用 Codex 内置生图生成一张白底蓝色玻璃球，不调用 KK 的生成 API”。完成后自动进入 KK 素材库与画布。
- 图片/文本卡片可选 Codex 模型；图片走内置生图，文案通过画布工具写回。卡片请求每次 1–4 份，参考图编辑尚未接入此入口。
- 展开额度查看共享窗口百分比和重置时间，可手动刷新；它包含其他 Codex 窗口的消耗，不是 KK 独立账单。
- 权限请求在 KK 显示。停止会请求中断；回执未知时锁住本轮写入，核对任务后再重连，避免重复生成。
- 连续发送、换 Codex 模型和重连继续同一会话；“新建 Agent 会话”才开始新对话。若服务已有当前项目未登记的会话，KK 会提示而不替换，按需要回原项目继续或明确新建。

## 模型与 API

对话有“默认”，卡片没有。菜单支持来源 → API 厂商 → 模型、返回、全部模型、当前页置顶；关闭保留所在页。模型来自当前 Codex 账号或已保存的 API 连接，重名模型按连接身份区分。

设置 → 模型供应商：保存已有连接，点击“刷新模型列表”。若 /models 不返回用途/尺寸，在“模型与参数”按供应商规格填写。尺寸例 `1024x1024, 1536x1024`，画布显示对应比例；未声明只用默认值。新模型未知用途时不能冒充已验证可生成。

Web API Key 只在当前页面内存，Desktop 延用系统凭据库。Google、豆包、WorkBuddy 本轮是禁用适配器项，菜单显示具体原因。

模型菜单顶部可搜索厂商、模型、4K 或 16:9 等已知信息，支持模糊输入和英文拼写建议。菜单只显示基础模型名，已发现的后缀变体在“型号参数”中选择，并原样发送对应厂商 ID。不会组合出厂商没有返回的型号。特殊命名可在设置 → 型号显示与搜索别名中补充。
