# 主线同步门禁修复规格

- `verify`：脱离分支的检出也能复用当前工作树。预算耗尽时，已登记的检出仍返回复用，而不是因为读不到分支名而失败。
- `delivery`：相对远端主线新增的变更包必须有五份交付文档，并绑到本审查分支上有变化的任务记录。
- `installer`：画布 schema 同步在内容没有变化时不得重写已跟踪文件，安装包回执才能看到干净的源码树。

## 续验约束

- 格式修复须逐文件等于基准源码经现有Prettier配置的输出，不修改门禁、基线或测试断言。
- schema同步只有读取错误`ENOENT`可进入创建；权限/其他读取错误必须原样传播，且在写入前停止。
- 222项原状态不因文本扫描或证据文件存在而批量升级/降级；历史失败保留，后继实现与当前验收分别记录。
- PR/分支包含关系以实际HEAD和祖先关系验证；非祖先不等于缺少所有源码，patch等价也不授权合并或删除。
- UI遵循当前Figma上下文与现有组件；浏览器、Native、真机、像素和Provider证据各自限定范围。
