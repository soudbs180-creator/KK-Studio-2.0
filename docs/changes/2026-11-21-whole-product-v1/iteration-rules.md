# 基线后迭代规矩（可持续加新）

- Task ID：TASK-WHOLE-V1-20261121
- 日期：2026-11-21
- 生效条件：**V1 用户整盘终验通过并在 verification 钉住版本身份之后**
- 平台顺序：Desktop → Web → Mobile（见 PROJECT_GOALS / ADR-011）

## 目的

整项目先有一版「已跑通且 UI 过关」的底盘；之后加新东西时，不回到模块各自迭代、永远没有整包验收。

## 每一轮新功能固定三步

1. **保基线**  
   不破坏 V1 主路径（项目 → 连接 → 文本 → 图片 → 回写 → 重开）与已过 UI。改动后跑主路径回归（自动化能跑的 + 必要时人工抽查）。

2. **新功能自己完整**  
   声明范围内含：真实行为或禁用原因；loading/success/error/cancel（适用 offline）；重开后行为符合声明。演示必须标 Prototype，不得与真结果同态冒充。

3. **抬基线**  
   用户或指定验收人确认后，更新能力地图/功能卡「当前能力」（替换式短结论），记录新版本身份。未确认不得宣称整包新完成。

## 完成与进度口径

| 正确 | 错误 |
| --- | --- |
| 整包/声明范围通过才算产品前进 | 任务 DONE 或本地 verify 绿 = 产品完成 |
| 已验证能力默认不重做 | 每个模块周期性推倒重来 |
| 旁路与演示后置或标明 | 横向同时开 Mobile+发布+规则+新模态 |
| 进度看：挡项减少、已计入增加、基线是否钉住 | 进度看变更包数量、哈希附录长度 |

## 技术方向闸门

- 新实现只走现行方案（共享 `src/` 领域与 UI 令牌、TaskHost/现行快照、Desktop 壳在 `src-tauri`）。
- 发现双轨/旧缝：迁完或禁用，禁止加长旧生命。
- 不借「跟上时代」换语言/框架；底座已是 React18 + TS + Vite + Tauri2 + Node24。
