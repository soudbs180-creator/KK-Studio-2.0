# 多模态提交与归档契约

复用 `CanvasImageCommandContext` → `createSubmissionLogic` → `CreationTask` → `useTaskExecution` → 原生 TaskHost/Provider → 素材库与 result 边。既有名称作为兼容入口保留，不另建队列或状态源。

1. 文本、图片、视频、音频均可提交；真实路径不依赖 `useLocalGeneration`、`localGeneration` 或 demo fixture。固定离线素材只用于显式 fixture 测试。
2. 创建时捕获模型、连接、参数、附件角色及首尾帧。持久化和重试保留同一输入；不支持的参数/参考必须在发送前明确拒绝，禁止偷偷改成无参考生成。
3. 视频采用已文档化的异步 Provider 协议；音频复用 OpenAI 兼容 speech 协议；本地 ComfyUI 继续以显式工作流为权威。新协议以适配器隔离，凭据仅在宿主/请求内存。
4. 原生持久宿主拥有异步任务；受理回执在继续轮询前落盘。取消停止等待并尝试供应商支持的取消；无法证明远端停止时保持 unknown，不伪造 cancelled 或自动重发。
5. 结果必须验证 MIME、归档原件后才可成功；视频/音频不能作为图片归档。重启读取原回执，不重复 POST。配置缺失、服务离线、失败、取消都有可操作状态。
6. 继续使用已有生成控件、设置入口和布局；仅替换演示文案与行为。Figma 当前组件页 `91:3` 已只读检查，无视觉重设计。

取舍：扩展已有统一链比另建音视频服务更少状态、更易恢复；同步图片接口不能承接异步视频。真实供应商终验与合成协议回归分开记录，缺证据不升级 REAL。

验收覆盖：四模态入口、未配置、参数/首尾帧、错误/离线、重复提交、取消、迟到回执、恢复、归档与 result 连线；完整 typecheck/lint/test、UI 门禁、浏览器与 Desktop 适用验证。
