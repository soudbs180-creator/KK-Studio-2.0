# ADR-002：演示后端化按波次推进，统一任务宿主

- 状态：Accepted
- 日期：2026-09-21
- 任务：FEATURE-SYSTEM / BACKEND-*

## 背景

视频/音频/文本节点、账号、积分、云同步、记忆、代理、连接器等目前是本地演示或占位。用户要求“全部开始写入后端”。其中一部分不依赖外部资源即可真实化，另一部分依赖供应商 Key、VPS/域名、身份与计费，不可能在同一轮无授权完成。

## 决策

- 分四波（见 `docs/features/BACKEND-ROADMAP.md`）：
  - Wave 1 本地可完成：图片参数（已完成）、文本节点、ComfyUI、MCP 自动调用、视频/音频链路、连接器。
  - Wave 2 桌面后端整合：T8 定 Core/Gateway/TaskHost 分工、T5 原生运行态、T7 安装验收、T9 Web 容量离线、桌面代理。
  - Wave 3 平台服务：账号/计费/云/记忆，依赖 T10 部署。
  - Wave 4 Mobile / Astra。
- 所有生成模态复用 FEAT-002 的任务宿主与门禁，不新建队列；逐模态替换 FEAT-025 演示 seam。
- 需要外部 Key/部署的，代码链路先就绪并标 PARTIAL/NOT VERIFIED，外部条件满足后再做付费/实机终验。

## 取舍

- 不在本轮一次性硬写平台账号/计费：没有服务器与支付授权，伪造可用状态违反 SPEC_BASELINE 硬规则。
- 不把 Node Gateway 强行塞进桌面：T8 未裁决 Core 边界前，桌面继续走已接入的 Rust TaskHost，避免两套引擎并存。

## 后果

- 每波有明确任务与验收依赖；外部阻断不阻塞本地工程。
- 状态推进必须伴随证据与卡片/账本更新，门禁兜底。
