# Intent：功能文档体系、状态看板与演示后端化启动

- Task ID：FEATURE-SYSTEM（含 BACKEND-IMAGE-PARAMS 样板）
- 日期：2026-09-21
- 来源：用户要求——规划清晰的文档目录，每个功能有可直接定位的文档且可持续新增；本地演示全部开始接入真实后端；任何 AI 接手都能依据规则知道哪些完成、哪些未完成、哪些待完善；信息打通、规范可落地。

## 实际目标

1. 建立“一个功能一张卡 + 机器可读登记册 + 生成看板 + 门禁”的功能文档体系。
2. 盘点现有全部功能，标注 REAL/PARTIAL/PROTOTYPE/PLANNED，串联代码、测试、证据与账本任务。
3. 给出本地演示后端化的分批路线图并登记账本任务。
4. 用一个完整样板（图片比例/清晰度真实透传，BACKEND-IMAGE-PARAMS）证明“PROTOTYPE→REAL”的闭环可执行。
5. 强化 AI 入口规则，保证换任何 AI 都按同一口径接手。

## 范围 / 非范围

- 范围内：docs/features 体系、门禁脚本、规则入口、账本任务、路线图、图片参数样板（Web+Desktop）。
- 非范围（本轮不做完，按路线图分批）：视频/音频真实供应商、账号/计费/云/记忆平台服务、Gateway 桌面搭载、Mobile、Astra 实现。
- 不提交、不推送（用户明确要求）；所有改动留在工作区。

## 验收

- AC1：每个现有功能有卡片，registry 与看板一致，`features:check` 零违规并并入 lint/verify。
- AC2：非 REAL 功能必须挂未 DONE 的账本任务，门禁可拦截。
- AC3：路线图覆盖全部 PROTOTYPE/PLANNED 功能并映射任务与外部依赖。
- AC4：图片参数在浏览器与 Rust 两条请求路径真实透传，有单测，UI 不再误导为“草稿”。
- AC5：AGENTS/AI_RULES/SPEC_BASELINE 指向新体系；typecheck、单测、构建、cargo check 通过。

## 风险与约束

- 以既有 task-ledger 为任务权威，功能卡片只做产品能力映射，不复制任务状态，避免第二事实源。
- 图片尺寸因供应商而异：发送通用 WxH，不支持时返回真实错误；不静默降级。
