## 2. 排序原则

1. **先接通、后换代**：G2 是"代码已写只差桥"的现成活，先收割；画布换代（G1）放 Wave 2，不与接通争抢回归面。
2. **先暴露、后生态**：MCP 服务端最小集让外部 Agent 先用起来，用真实使用反馈再定插件市场形态。
3. **换代走灰度**：FEAT-001 是 REAL 功能，禁推倒；适配层 + feature flag + 双实现并存，证据同态后才退役自研实现。
4. **治理不追赶**：竞品快但无治理；本路线每项仍过全部门禁、REAL 仍需同态运行证据。
5. **平台层不让路**：账号/云同步/积分/三端同态按既定节奏，不因竞品压力加速或降级。

## 4. 路线项明细

> 每项格式：目标 / 范围（做·不做）/ 关联 FEAT / 验收 / 依赖 / 验证 / 风险与放弃条件。批准后逐项转账本任务时补 branch/worktree/owner。

### OPT-001 路线立项与账本登记（W0）

- **目标**：把 W1–W4 各项转成正式账本任务，明确依赖图与并行边界。
- **范围**：只写治理工件（task-ledger 条目、FEAT 卡更新）；不动产品代码。
- **验收**：每个任务有 goal / scope / acceptance / dependencies / affectedModules / featureIds；依赖图无环；W1 三项标 READY。
- **依赖**：用户批准本路线。
- **验证**：`npm run features:check`、`npm run governance:check` 通过；账本与 FEAT 注册表一致。
- **风险**：任务粒度过大导致 worktree 长期悬挂——单项超过一个可合并单元时拆分为主/子任务。

### OPT-002 画布底座选型 ADR + 许可评估（W0）

- **目标**：在 tldraw SDK（商业授权，捆绑分发、无 key 显示 badge）、Excalidraw（MIT）、leafer（影策/BeefTV 在用）、继续自研四条路中出 ACCEPTED 决策。
- **范围**：做——选型矩阵（许可、功能覆盖、打包体积、Tauri/Web 双端、补丁空间、社区活跃）、最小验证原型（各库跑通"节点+连线+视口+导出"最小链）、ADR 记录"不选择的方案及理由"。不做——引入任何竞品源码。
- **关联 FEAT**：FEAT-001。
- **验收**：ADR ACCEPTED；原型在 Web 开发态有 DOM/截图证据；许可结论成文（含 tldraw 商业采购成本评估）。
- **依赖**：无（可与 OPT-003 并行）。
- **验证**：`npm run typecheck` + 原型构建；UI 运行链（1421 端口证据）。
- **风险与放弃条件**：若四案均不满足"双端 + 许可 + 可补丁"硬约束，放弃 Wave 2 换代，改为自研画布"加固"专项（补测试与文档），并在 ADR 留 tombstone。

### OPT-003 MCP 服务端契约 spec（W0）

- **目标**：定义 KK 画布与生成能力的 MCP 工具面（服务端侧），与既有出站客户端共用契约层。
- **范围**：做——工具清单初版（查看画布/放置素材/触发生成/查询任务状态/读取产物/ask user）、参数 schema、错误语义（与统一任务态契约一致）、安全模型（loopback 绑定、token、工具白名单、审计）。不做——服务端实现（OPT-103）。
- **关联 FEAT**：FEAT-012、FEAT-030。
- **验收**：spec 过 review；每个工具有 AC 与失败边界；与 `agentCanvas` 现有契约无二义性冲突。
- **依赖**：无。
- **验证**：schema 可通过契约测试（mock  round-trip）。
- **风险**：契约过度设计——工具数以"覆盖一次端到端创作"为限，超出部分进后续版本。

### OPT-101 ComfyUI 出图链接线（W1，最高优先级）

- **目标**：让 FEAT-004 从"代码已写未接"到本地真实出图。
- **范围**：按 FEAT-004 卡既有 gap 清单执行——① 前端 invoke 桥调 Rust `comfyui_*`；② 接入 `submitImageCommand → executeTask`，复用 FEAT-002 的 reservation/health/journal；③ 工作流持久化、逐任务取消（只删指定队列项）、归档与重启恢复；④ 用户选定 ComfyUI 根目录/工作流/模型（EXT-COMFY 验收条件）。
- **关联 FEAT**：FEAT-004（主）、FEAT-002、FEAT-031。
- **验收**：本机 ComfyUI 实例上完成"文本生成→图片生成→结果回写画布→取消→重启恢复"全链路真实回执；服务端参考实现既有 HTTP 测试保持通过；双端（Desktop/Web）语义一致或 Web 侧显式降级说明。
- **依赖**：本机存在可用 ComfyUI 实例（**当前未确认，见 §6 风险 R2**）；OPT-001 账本任务。
- **验证**：真实运行回执 + `tests/unit/generationServerProvider.test.ts` + 相关回归；UI 运行链证据。
- **风险与放弃条件**：若本机短期无 ComfyUI 环境，先交付"环境就绪度检查 + 服务端路径联调脚本"，把真实出图回执列为后续验收条件，**不得以 mock 冒充**。

### OPT-102 ComfyUI 工作流库可用化（W1）

- **目标**：FEAT-005 的本地工作流管理与 OPT-101 的出图链打通（选工作流→填参→提交→进度→回写）。
- **范围**：做——工作流选择 UI、参数表单（由 api.json 输入 schema 生成）、进度展示（复用 `comfyUiProgress`）。不做——工作流编辑器（竞品亦多为 JSON 管理）。
- **关联 FEAT**：FEAT-005、FEAT-004。
- **验收**：从工作流库任选一个 api.json 完成一次真实出图；逐任务取消生效。
- **依赖**：OPT-101。
- **验证**：同 OPT-101 运行回执。
- **风险**：参数 schema 与工作流实际输入漂移——以 ComfyUI `/object_info` 动态校验，失败即拒收并提示。

### OPT-103 MCP 服务端最小集（W1）

- **目标**：实现 OPT-003 契约的最小工具集，使外部 Agent（Claude Code / Codex 等）能操作 KK 画布。
- **范围**：做——服务端路由、工具分发到"已打开的 ComfyArt 式执行面"（KK 侧为运行中的画布会话）、任务态查询。不做——插件市场、多项目隔离（后续）。
- **关联 FEAT**：FEAT-012、FEAT-030。
- **验收**：用任一外部 MCP 客户端完成"查看画布→放置素材→触发生成→读取结果"一次真实回执；未授权调用被拒绝并有审计记录。
- **依赖**：OPT-003；与 OPT-101 可并行（工具面先行，生成类工具后接通）。
- **验证**：MCP 契约 round-trip 测试 + 真实客户端联调回执 + 安全用例（无 token / 错 token / 越权工具）。
- **风险**：本地服务暴露面——默认仅 loopback + 显式开启；开启时强制 token；文档明示风险。

### OPT-201 画布适配层抽象（W2）

- **目标**：在自研画布之上抽 `CanvasAdapter` 接口（节点/连线/视口/历史/导入导出/事件），使底座可替换。
- **范围**：做——接口定义、自研实现适配、调用方改走适配层。不做——换库（OPT-202）。
- **关联 FEAT**：FEAT-001。
- **验收**：全部画布调用方经适配层；`npm test` 画布相关回归零新增失败；接口有契约测试。
- **依赖**：OPT-002 的 ADR（接口形态随选型结论微调）。
- **验证**：typecheck + 定向回归 + 画布 UI 运行链（同状态截图对比）。
- **风险**：抽象泄漏——接口只收"画布通用概念"，不收任一库的私有类型；泄漏即回退重划。

### OPT-202 画布库接入（W2）

- **目标**：按 ADR 结论实现第二个 `CanvasAdapter`（tldraw / Excalidraw / leafer 之一）。
- **范围**：做——适配实现、双端（Desktop/Web）构建、许可文件归位（如 tldraw 需随包许可与 badge 处理）。不做——一次性删自研实现。
- **验收**：新实现通过 OPT-201 全部契约测试；构建产物含许可声明；体积增量在 ADR 预算内。
- **依赖**：OPT-201、OPT-002。
- **验证**：契约测试 + 构建 + UI 运行链。
- **风险**：库的 Tauri/Web 差异（如 tldraw 资源加载）——双端分别出证据，不允许单端证据外推。

### OPT-203 画布灰度替换与自研退役（W2）

- **目标**：feature flag 灰度，默认切新底座；自研画布退役为只读兼容（旧项目可打开、不新建）。
- **范围**：做——flag、迁移（旧项目数据→新底座格式）、退役方案与文档。不做——保留双写（避免双源真相）。
- **验收**：新旧项目均可在新底座打开并有同态证据；flag 关闭时行为回退路径清晰；`components/canvas` 自研渲染代码退役或仅存迁移读取器；FEAT-001 保持 REAL。
- **依赖**：OPT-202。
- **验证**：回归全量 + 迁移用例 + 双端运行链 + features:check。
- **风险**：回归面爆炸——按"连接/手势/标注/导出"四类切片逐块验收；任一切片失败即停在该切片，不整体回滚也不带病合并。

### OPT-301 Agent 三段式落地（W3）

- **目标**：把"规划→执行→回读检查"写进 FEAT-030 编排契约：Agent 先出计划（含节点/连线/参数），用户确认后执行，执行后读回产物核对。
- **范围**：做——契约扩展、计划态 UI（可编辑的计划清单）、执行后核对报告（产物 vs 计划差异）。不做——自治 Agent（无确认全自动）。
- **关联 FEAT**：FEAT-030、FEAT-016。
- **验收**：一次"一句话需求→计划→确认→执行→核对"端到端回执；核对报告能指出缺失/失败节点；每阶段有人工确认点（顺带解决 G8）。
- **依赖**：OPT-103（工具面）、OPT-101（生成接通）。
- **验证**：端到端运行回执 + 编排契约测试。
- **风险**：计划态与任务态混淆——计划是 proposal，任务态仍归统一任务态契约（FEAT-031），不建第二套状态机。

### OPT-302 Skills 版本管理（W3）

- **目标**：FEAT-011 补齐安装锁定、版本回退、私人改写（参照 BeefTV 市场设计与无限画布 skills-lock）。
- **范围**：做——skills-lock 式锁定文件、版本元数据、回退、私人副本。不做——公开市场与投稿送审（OPT-401 之后）。
- **关联 FEAT**：FEAT-011。
- **验收**：安装指定版本→更新→回退→私人改写全链路回归；锁定文件进项目包导出。
- **依赖**：OPT-001。
- **验证**：定向回归 + 导出/导入 round-trip。
- **风险**：与既有技能加载机制双轨——直接扩展现有机制，禁第二套加载器。

### OPT-303 持久任务编排增强（W3）

- **目标**：FEAT-024 补齐长任务的持久化、重试与恢复策略；评估是否引入 Temporal（默认轻量：journal + 恢复，ADR 记录不选 Temporal 的理由）。
- **范围**：做——任务 journal  schema、崩溃恢复、失败分类（与 COMPETITOR_CONCLUSIONS 既有结论一致：未知/外部受理状态与普通失败区分）。不做——自建工作流引擎。
- **关联 FEAT**：FEAT-024、FEAT-031。
- **验收**：杀进程恢复后任务态一致；重试保留 task identity 与 revision；既有 8 项环境性测试失败基线不恶化。
- **依赖**：OPT-101（本地任务宿主打通后）。
- **验证**：恢复用例（模拟中断）+ 全量测试对比基线。
- **风险**：与 reservation/health/journal 现有语义重叠——先读现有实现再扩展，禁平行账本。

### OPT-401 插件脚手架与包格式（W4）

- **目标**：参照 Toonflow 四 scaffold，定义 KK 插件包格式 + 至少一个生成器（节点插件优先）。
- **范围**：做——包 manifest、加载/隔离模型、`create:*` 脚手架、文档。不做——公开托管市场。
- **关联 FEAT**：features/plugins、FEAT-013。
- **验收**：第三方按文档开发一个演示插件并在 Desktop/Web 双端加载；加载失败有隔离与错误面。
- **依赖**：W2 完成（插件挂新画布底座）；OPT-302（版本机制可复用）。
- **验证**：演示插件回归 + 契约测试。
- **风险**：安全面（第三方代码执行）——默认关闭、显式开启、权限声明；禁隐式信任。

### OPT-402 3D 导演台（W4）

- **目标**：画布内 3D 预演：人物站位、镜头距离与构图，输出为生成参考图/提示词。
- **范围**：做——three/react-three-fiber 预演层、机位参数导出。不做——完整 3D 资产管线。
- **关联 FEAT**：FEAT-001 扩展（新功能先建卡）。
- **验收**：P0 e2e（摆放→构图→导出参考）通过；与 2D 画布坐标互转正确。
- **依赖**：OPT-203（新底座）。
- **验证**：Playwright e2e + 视觉证据。
- **风险**：与画布交互冲突（3D 抢占手势）——显式模式切换，禁全局手势劫持。

### OPT-403 电商垂直场景验证（W4，需用户确认）

- **目标**：以 Canvex（电商无限画布）为参照，验证 KK 在电商视觉场景的差异化切入（商品图/多角度/场景合成）。
- **范围**：做——场景调研、最小场景闭环（商品参考→多角度→场景图→导出）、验证报告。不做——新平台层承诺。
- **验收**：一份含真实回执的场景验证报告；明确"做/不做/缓做"结论。
- **依赖**：W1 出图链 + W2 画布；用户确认场景优先级。
- **验证**：场景运行回执。
- **风险**：场景漂移——严格限定在"验证"，不扩成新 feature 开发。

### OPT-404 外部 Skills 生态对接评估（W4）

- **目标**：评估接入外部影视创作 Skills 生态（libtv-skills 1.2k★、screen-creative-skills 475★ 等）的许可、质量与适配成本。
- **范围**：做——许可审计、抽样质量评估、导入适配器设计。不做——默认捆绑外部内容。
- **验收**：评估报告含许可清单与"可导入/需授权/不可用"三分类。
- **依赖**：OPT-302。

## 7. 治理挂接（批准后动作）

1. **建账本任务**：按 §4 每项建条目（id/title/goal/scope/acceptance/dependencies/affectedModules/featureIds/priority/risk），依赖图与本文件一致。
