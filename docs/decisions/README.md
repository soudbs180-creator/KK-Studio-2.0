# ADR（Architecture Decision Records）规则

本目录沉淀 KK Studio 每个重要决策的"为什么"。功能状态在 `docs/features/`，工程规则在 `AGENTS.md` / `AI_RULES.md`，但**为什么选 A 不选 B** 只能在这里查。

## 格式

每个决策一份文件：`NNNN-kebab-title.md`，编号从 0001 起，只增不改。后续决策推翻旧 ADR 时，新 ADR 里写"取代 NNNN"，旧 ADR 保留原文并在开头标注"已被 NNNN 取代"。

每份 ADR 固定 6 段：

1. **日期**
2. **背景**——当时遇到什么问题、有什么约束
3. **决定**——选了什么
4. **原因**——为什么不选其他方案
5. **后果**——后续什么事会因此变容易/变难
6. **反对意见**——当时谁（哪个方案）被驳回了

## 谁来写

- 用户做的产品/视觉决策，由 AI 整理成 ADR
- AI 自己做的技术决策，合并 PR 时顺手补一份
- 不确定是不是"决策"时，问自己：3 个月后回来改这块代码，会不会想知道"为什么当初这么写"？会，就写。
